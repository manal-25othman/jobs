# حزمة مراجعة الخبير/ة (SME) — مطوّر/ة واجهات ويب مبتدئ
**الإصدار المُراجَع:** 0.2.0 · **الحالة:** مسودة صاغها مساعد، **غير معتمدة** · **الزمن التقديري لإكمال هذه الحزمة:** ٩٠–١٢٠ دقيقة

## ما نطلبه منك
أنتِ/أنت خبير/ة واجهات ويب. نريد حكمك على **الواقعية** لا على النظام: هل هذا ما يُطلب فعلًا من مبتدئ في فريق ويب سعودي صغير إلى متوسط؟ هل المهام والأنشطة والمعايير عادلة له؟ لا تحتاجين أن تعرفي كيف تُخزَّن البيانات أو كيف يعمل التقييم داخليًا.
**لكل بند:** ضعي قرارًا (`approve` / `revise` / `reject`) وتعليقًا قصيرًا عند `revise`/`reject`. إن كان البند خاطئًا فما مدى ضرره: **حرج** = يمنح مبتدئًا وصفَ مهارة لا يستحقه · **عالٍ** = قد يُنجَح/يُفشَل ظلمًا · **متوسط** = يشوّش · **منخفض** = صياغة.
**قاعدتان ثابتتان لسنا نراجعهما:** (١) المسار **عام بلا إطار عمل** (لا React ولا Vue…) — الأطر تُتعلَّم في الفريق. (٢) أعلى ما يمنحه أي نشاط الآن هو «أثبت» (Demonstrated)؛ لا «موثَّق» (Verified) بعد.
**ملاحظة:** ٥ مهارات تستند إلى معايير رسمية (HTML · CSS · JavaScript · WCAG · النماذج). حكمك عليها مطلوب الآن، لكن **اعتمادها النهائي** ينتظر أيضًا إرفاق المراجع الرسمية — هذا شأننا لا شأنك.

## هـ. الأنشطة الثلاثة — هل التجربة عادلة؟

كل الأوزان (0.5 – 1.5) والعتبات **مقترحة** الآن. جدول مفصَّل لكل معيار (لماذا الرقم، وماذا يحدث لو كان عاليًا أو منخفضًا) في `docs/evaluation/RUBRIC-WEIGHTS-THRESHOLDS-REVIEW.md`. **نطلب رأيك الأولي فقط**؛ الاعتماد النهائي يأتي بعد أول عيّنة من تسليمات حقيقية تراجعينها. **لا تُضخَّم الأوزان لتعويض ضعف تغطية مهارة.**
| السؤال | رأيك |
|---|---|
| هل الأوزان 1.5 لـ«حالات البيانات» و«انتقالات الحالة» و«التجاوب أُصلح» و«التحقق أُصلح» و«السبب الجذري» و«التصفية عبر الحالة» مبرَّرة أمام 1 للبنية؟ | |
| هل 75٪ عتبة اجتياز معقولة لمبتدئ في نشاط بمساعد AI؟ | |
| هل «جزئي» يكفي لاحتساب مهارة، أم يلزم «مكتمل» لمهارة أساسية؟ | |

## ح. الدليل المتوقَّع — ماذا يُثبت المهارة فعلًا
| المهارة الأساسية | ما تسلّمه الأنشطة | السؤال | القرار |
|---|---|---|---|
| HTML الدلالية | ملف HTML في نشاطين | يكفي الملف وحده لمستوى `working`، أم يلزم شرح للبنية؟ | |
| CSS متجاوب | ملف CSS في نشاطين (واحد منهما اختياري) | يكفي نشاط واحد إلزامي؟ | |
| JavaScript | JS في نشاطين + ملاحظة قرار | كان مقترحًا «دفاع حي» (حوار) — هل هو شرط لمبتدئ أم تطلّع؟ | |
| حالة الواجهة · حالات البيانات | JS + ملاحظات في نشاطين | كافٍ؟ | |
| التصحيح · قراءة الكود (مساندة) | ملاحظات وكود | كان مقترحًا «دفاع حي» و«أثر عملية (Git)» ولا نوفّرهما — تُقبل الفجوة أم تُعاد صياغة التوقُّع؟ | |
