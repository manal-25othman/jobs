# حزمة مراجعة SME — Junior Web / Frontend Developer (`trk_frontend_junior@0.1.0`)
**الحالة:** DEMO / DRAFT / **NOT SME APPROVED** · **المطلوب من المراجع/ة (SME):** قرار مكتوب لكل بند (`approve` / `revise` / `reject`) مع تعليق. **لا شيء في هذه الحزمة معتمد، ولا يعتمده هذا المستند** — القرار المسجَّل هو ما يُكتب في `review_log` بالأمر أدناه، بالاسم والسبب والزمن.

**كل صف في الحزمة صاغه مساعد** (`drafting_aid = ai_assisted`) من مصدر داخلي واحد (`src_naqla_frontend_pack_v0_1` · موثوقية `low`) مع إشارة إلى معايير رسمية **لم تُلتقط لقطاتها بعد** (`OPEN-042`). الجدول الكامل لما ينقصه مصدر: `FRONTEND-SOURCE-GAPS.md`.

## كيف تُسجَّل القرارات
الحزمة موسومة **DEMO**، والقاعدة ترفض بنيويًا `sme_reviewed`/`approved` لأي صف demo (D-081). لذلك الاعتماد الحقيقي يجري على **نسخة مراجعة** تُنشأ من الصف التجريبي دون المساس به (`OPEN-040`):
```
# 1 · إنشاء نسخة مراجعة غير تجريبية (curated) من الصف التجريبي — الأصل يبقى كما هو
node scripts/career-data.mjs promote <kind> <demo-uuid> --by <reviewer-uuid> --note "<why now>"
# 2 · تصحيح مُسجَّل على النسخة (الحقل · من · إلى · السبب) — كل تصحيح صف في content_promotion.corrections
node scripts/career-data.mjs promotion-correction <promotion-uuid> --field <name> --from "<old>" --to "<new>" --by <uuid> --reason "<why>"
# 3 · مراجعة SME على النسخة (بالاسم؛ --minutes يُقاس؛ --conflict إن كان المراجع هو المؤلف)
node scripts/career-data.mjs review <kind> <canonical-uuid> sme_reviewed --role sme --by <uuid> --label "<name>" --reason "<what was checked>" --minutes 12
node scripts/career-data.mjs review <kind> <canonical-uuid> approved     --role sme --by <uuid> --label "<name>" --reason "<why>"
# 4 · النشر (مالكة المنتج) — ثم إغلاق الترقية: الصف التجريبي يصير superseded ويبقى مُعرَّفًا
node scripts/career-data.mjs review <kind> <canonical-uuid> published --role product_owner --by - --label "R-1" --reason "..."
node scripts/career-data.mjs promotion-complete <promotion-uuid> --by <uuid>
```
`kind` ∈ `skill` · `target_role` · `task` · `activity_spec` · `rubric_version`. النسخة تحمل `promoted_from_id` إلى الأصل التجريبي، والسجل `content_promotion` يحفظ: المصدر التجريبي · المراجع · القرارات · التصحيحات · زمن الاعتماد · السجل الكانوني الناتج.

# B. المهارات الأساسية الخمس — `is_core_for_role = true`
**قاعدة:** «أساسية» صفة على **ربط الدور** لا على المهارة (DF-6)؛ عددها محصور ٤–٥ (`validatePack`). كل واحدة تحتاج: مسار دليل (Q06) · نشاطان يقيسانها · بنود مربوطة · `Demonstrated` ممكن. **`Verified` غير ممكن لأي منها** (لا نشاط `can_yield_verified`؛ D-059 · Q09) — هذا واقع المنصّة لا عيب في الحزمة.
