# الوثيقة 13 — Functional Capability Map
> خريطة القدرات الوظيفية لكل المنتج (لا Phase 1 فقط). **مصدر الاشتقاق لمتطلبات SRS الوظيفية لاحقًا.**
> `Status`: `BUILT` · `THIN` · `CONTRACT` · `REGISTERED` (سجل الرؤية) · **الوكلاء** بمعرّفاتهم A01–A19.

## أ. الهوية والوصول

**CAP-01 — التسجيل والدخول** · `P1` · `BUILT` · الفاعلون: User · System
- المدخل → المخرج: بيانات تسجيل → `Person` + جلسة
- الاعتماديات: CAP-03 · الكيانات: `Person` · `Consent` · الوكلاء: —
- نية القبول: مستخدم جديد ينشئ حسابًا ويدخل، **ولا تُعالَج بياناته بلا موافقة مسجّلة**.

**CAP-02 — حجز اسم المستخدم** · `P1` · `BUILT` · User · System
- اسم مقترح → `UsernameReservation` + حجز `/u/{username}` غير منشور
- الاعتماديات: CAP-01 · الكيانات: `UsernameReservation` · الوكلاء: —
- القبول: الاسم محجوز دائمًا ومحميّ من الانتحال، ولا يُنشر حتى P4.

**CAP-03 — إدارة الموافقات** · `P1` · `BUILT` · User · System
- اختيارات المستخدم → `Consent[]` (append-only)
- الكيانات: `Consent` · القبول: كل معالجة تشير إلى أساس موافقة قائم؛ السحب يسري فورًا ومستقبلًا.

**CAP-04 — التصدير والحذف** · `P1` · `BUILT` · User · Platform Admin
- طلب → حزمة تصدير / تنفيذ حذف وفق `RetentionPolicy`
- الكيانات: كل فئات DC · القبول: التصدير كامل للفئات المسموحة، والحذف يحترم التعليق القانوني ويُنشر كحدث تدقيق.

**CAP-05 — عضوية المؤسسة** · `P5` · `REGISTERED` · Org Admin · User
- دعوة/انضمام → `Membership` فوق `org_id` المحجوز · القبول: تفعيل بلا هجرة بيانات، **وبلا كشف محتوى عمل فردي للمؤسسة دون موافقة**.

## ب. التوجّه المهني

**CAP-06 — الملف المهني** · `P1→P2` · `THIN` · User
- 8–12 حقلًا → `CareerProfile` بوسم `user_generated.declared`
- القبول: **لا يُنتج دليلًا ولا مستوى مهارة بأي حال**.

**CAP-07 — تحديد الهدف** · `P1→P2` · `THIN` · User · A02
- اختيار دور مرجعي → `Goal` · الاعتماديات: CAP-13 · القبول: هدف خارج المسارات المدعومة يُقابَل بإفصاح صريح لا بتوليد مسار وهمي.

**CAP-08 — التشخيص (Career Snapshot)** · `P1→P2` · `THIN` · User · A02 · A18
- `CareerProfile` + `Goal` + `Role` → `Snapshot`
- الكيانات: `Snapshot` · `Gap` · القبول: كل عبارة موسومة بمصدرها، وفشل النموذج يُنتج نسخة حتمية لا صمتًا.

**CAP-09 — حساب الفجوات** · `P1` · `BUILT` · System
- متطلبات الدور − المستوى الحالي → `Gap[]` بوسم `system_derived` (D-020)
- القبول: حتمي وقابل لإعادة الحساب بعد كل تقييم، مع `derivation_rule_version`.

**CAP-10 — خطة 30/60/90** · `P2` · `CONTRACT` · User · A02 · A15
- `Gap[]` + بيانات الأداء → `Plan` · القبول: الخطة مشتقة من أداء فعلي لا من تقييم ذاتي.

## ج. المحتوى والتأليف

**CAP-11 — تأليف الأنشطة وإصدارها** · `P1` · `BUILT` · Content Author · Platform Admin
- تصميم → `ActivitySpec@version` منشور
- القبول: نشاط يمنح `Verified` **لا يُعتمد** بلا Integrity Checks (I1+I2+I3) ولا بلا `skill_mapping` (D-013).

**CAP-12 — تأليف الرُبريكات ومعايرتها** · `P1` · `BUILT` · Content Author · Human Reviewer
- بنود + أوزان + عتبات → `RubricVersion` منشور + `ScoringPolicy@version`
- القبول: لا نشر قبل اتفاق ≥80% مع الحكم البشري على مجموعة ذهبية تتضمن مخرَج AI خام.

**CAP-13 — تأليف الأدوار المرجعية** · `P1` · `BUILT` · Content Author
- → `Role` بمتطلبات وأوزان وتمييز Core/مساند · القبول: كل فجوة تُنسب إلى متطلب صريح فيه.

**CAP-14 — سجل موارد التعلّم** · `P1→P2` · `THIN` · Content Author · A07
- → `LearningResource[]` مُنسّق · القبول: **الترشيح من السجل حصرًا** — لا اختلاق روابط.

## د. العمل والتنفيذ

**CAP-15 — إسناد النشاط** · `P1` · `BUILT` · System · A19 · A07
- `Gap` الأعلى أولوية → `Activity` + `WorkItem(platform_activity)` + موعد
- القبول: اختيار حتمي مُعلَّل، وبديل واحد عند الرفض.

**CAP-16 — تنفيذ النشاط** · `P1→P3` · `THIN` · User
- عمل المستخدم → تقدّم + مسودات + إشارات عملية **مُعلَنة مسبقًا**
- القبول: بطاقة سياسة AI ظاهرة قبل البدء؛ لا تتبع خفي.

**CAP-17 — التفاعل مع المدير الافتراضي** · `P1→P3` · `THIN` · User · A11 (→A10 · A12)
- رسالة → `ManagerTurn` ضمن سقف الـSpec
- القبول: لا يعطي الحل ولا يلمّح للدرجة، **ووسم دائم أنه نظام لا إنسان**.

**CAP-18 — Project / Evidence Hub** · `P1→P2` · `THIN` · User
- مشروع/نشاط → `WorkItem` بالمصادر الخمسة + تقدّم + معالم + ملفات + مهارات + أدلة + إنجاز
- القبول: سلسلة `Project → Progress → Evidence → Skill → Achievement → Assets` مرئية للمستخدم؛ و`self_reported` **لا يصل `Verified`** ويُقال ذلك صراحة.

**CAP-19 — Validation Activity (الترقية)** · `P1` · `THIN` · User · A13 · A18
- مشروع `self_reported` + نشاط تحقق قصير → `platform_observed` (D-018a)
- القبول: **بلا مطالبة المستخدم بإعادة المشروع كاملًا**.

## هـ. التقييم والتحقق

**CAP-20 — التسليم وإقرار AI** · `P1` · `BUILT` · User
- محتوى + إقرار → `Submission` مقفل + `AIUsageDisclosure` + `Artifact[]`
- القبول: الإفصاح **لا يخفض الدرجة بذاته**؛ وإعادة التسليم نسخة جديدة لا استبدال.

**CAP-21 — الفحوصات الحتمية** · `P1` · `BUILT` · System
- → `DeterministicCheckResult[]` · القبول: **تسبق أي استدعاء نموذج**؛ الرسوب يوقف الخط مع فرصة تصحيح واحدة.

**CAP-22 — Integrity Checks** · `P1` · `BUILT` · System (+ نموذج محدود)
- → `IntegrityCheckResult[]` · القبول: فحص حاسم غير مكتشَف **يسقّف الادعاء عند `Practiced`**؛ وليست أداة اتهام.

**CAP-23 — التقييم بالرُبريك** · `P1` · `BUILT` · A13
- → `EvaluatorResult[]`: درجة + مبرر + مقتطف + مهارة
- القبول: لا درجة بلا بند ومقتطف؛ **ولا نتيجة تخمينية عند الفشل** — طابور مراجعة بشرية.

**CAP-24 — استخراج الدليل** · `P1` · `BUILT` · A14
- → `Evidence[]` (غير قابلة للتعديل) · القبول: **"لا دليل" نتيجة مشروعة** تُعرض بوضوح.

**CAP-25 — بوابة التحقق** · `P1` · `BUILT` · A18
- → `Verification` (V1–V8) + الشرط الساقط · القبول: **تخفض أو تثبّت ولا ترفع**؛ والوضع الآمن عند العطل هو الخفض.

**CAP-26 — حساب مستوى المهارة** · `P1` · `BUILT` · System
- → `Claim.level` + `level_reason` + `recency_status` بوسم `system_derived`
- القبول: **`Activity Score ≠ Skill Verification Level`** (الثابت التاسع)؛ حتمي بالكامل.

**CAP-27 — المراجعة البشرية** · `P1` · `BUILT` · Human Reviewer
- → قرار موثّق (تثبيت/خفض/**رفع**) · القبول: `human_override_up` بحقوله الثمانية، **ولا رفع مع شرط جوهري مفقود** (D-021).

**CAP-28 — الاعتراض** · `P1` · `BUILT` · User · Human Reviewer
- → تقييم مراجعة جديد **لا يستبدل الأصلي** · القبول: قرار نهائي مُعلَّل يُحتسب في مقياس الاتفاق.

## و. المخرجات المهنية

**CAP-29 — الإنجاز** · `P1` · `BUILT` · System
- أحداث → `Achievement` بوسم `system_derived` · القبول: **ممنوع بنيويًا بلا دليل**.

**CAP-30 — CV و LinkedIn** · `P1→P2/P4` · `THIN` · User · A17 · A18
- `Evidence[]` → عبارات مرتبطة بمعرّفات أدلة · القبول: لا اختراع؛ واللغة لا تتجاوز المستوى؛ وتعديل المستخدم يُسقط وسم التوثيق.

**CAP-31 — الحالة الدراسية ونشرها** · `P1→P4` · `THIN` · User · A16 · A18
- → `Projection(case_study)` + رابط · القبول: فحص خصوصية قبل النشر، ونشر **بموافقة صريحة فقط**.

**CAP-32 — الملف العام `/u/username`** · `P4` · `CONTRACT` · User
- → `PublicProfile` فوق الإسقاطات · القبول: يُفتح بلا هجرة أسماء ولا كسر روابط.

## ز. المرافقة والتوجيه

**CAP-33 — Personal Career Companion** · `P1→P2` · `THIN` · User · A01
- حالة النظام + سؤال → رسالة + إجراء واحد + سبب
- القبول: **يشرح ولا يخطط**؛ ولا يتوقف عند نفاد الميزانية بل يتدرّج إلى النمط الحتمي (D-014).

**CAP-34 — الإجراء التالي** · `P1` · `BUILT` · System · A19
- فجوات محدّثة → `NextAction` واحد · القبول: مُعلَّل بفجوة محددة، ولا تكرار للنشاط نفسه.

**CAP-35 — التغذية الراجعة التطويرية** · `P1→P2` · `THIN` · A15
- بنود ضعيفة → ملاحظات + إجراء · القبول: نقد العمل لا الشخص؛ ولا تغيير للدرجة.

**CAP-36 — توصية التعلّم** · `P1→P2` · `THIN` · A07
- `Gap` → `LearningNeed` → `ResourceRecommendation` + **تطبيق إلزامي**
- القبول: **ترشيح بلا تطبيق مرفوض بنيويًا**.

## ح. التشغيل والحوكمة

**CAP-37 — التنسيق (Journey Engine)** · `P1` · `BUILT` · A19
- أحداث → قرارات توجيه + نطاق سياق + سقف تكلفة · القبول: حتمي بلا نموذج في P1؛ لا حلقات؛ لا تشغيل لكل الوكلاء.

**CAP-38 — بوابة الذكاء الاصطناعي وضبط التكلفة** · `P1` · `BUILT` · System
- كل استدعاء → `CostRecord` + تطبيق الميزانية والتوجيه والتخزين المؤقت
- القبول: **لا استدعاء بلا سجل**؛ والخط الحرج لا يُخفَّض أبدًا.

**CAP-39 — المصدر والتدقيق** · `P1` · `BUILT` · System
- كل حقيقة → `Provenance` + سلسلة نسب · القبول: **"لماذا نقول هذا" تُجيبها صفحة واحدة**، وإلا لا يُعرض الادعاء.

**CAP-40 — سجل الأحداث** · `P1` · `BUILT` · System
- → `Event` append-only · القبول: كل فعل ذي معنى مُسجَّل؛ ولا حذف.

**CAP-41 — التذكيرات والتنبيهات** · `P1→P5` · `THIN` · System · A01
- أحداث → تذكير واحد في P1 · القبول: تجاهل مرتين يوقف التذكير (لا مطاردة).

**CAP-42 — إنفاذ الاحتفاظ والخصوصية** · `P1` · `BUILT` · System · Platform Admin
- `RetentionPolicy` → حذف/إخفاء هوية/تعليق قانوني · القبول: كل تنفيذ يُنشر كحدث تدقيق، والتعليق يسبق الحذف المجدول.
