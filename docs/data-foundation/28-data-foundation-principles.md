# الوثيقة 22 — Data Foundation Principles
> تصميم أساس البيانات لـCareer OS. **لا كود · لا SQL · لا قاعدة بيانات · لا جمع بيانات فعلي.**
> ملزم بالثوابت التسعة و`14-provenance-architecture.md` و`12-rubric-architecture.md` و`ARCH-REQ-TRACK-01..05`.

## 1. المبادئ الحاكمة

| # | المبدأ | الأثر العملي |
|---|---|---|
| **DF-1** | **الحقيقة مُهيكَلة، والسرد مُستَرجَع** | كل ما يُحسب عليه قرار (فجوة · عتبة · مستوى · توصية) **بيانات مُهيكَلة**. النصوص الطويلة مواد استرجاع لا مصادر حقيقة (§7) |
| **DF-2** | **لا سجل منشور بلا مصدر ومراجعة** | `provenance` + `review_status` إلزاميان على كل سجل في الطبقة المنشورة |
| **DF-3** | **المعرّفات دائمة والأسماء متغيرة** | `skill_id` لا يتغير أبدًا · الأسماء والصياغات تتغير بحرية · **المعرّف لا يُشتق من اسم** |
| **DF-4** | **بيانات السوق ليست حقيقة الدور** | إشارات السوق **تقترح** تغييرًا عبر المراجعة، ولا تُعدّل متطلبات الدور آليًا أبدًا (§6) |
| **DF-5** | **المسار معطى محتوى** | إضافة مسار = حزمة بيانات جديدة، **بلا تغيير في المحركات** (ARCH-REQ-TRACK-03) |
| **DF-6** | **المهارات مشتركة، الأدوار محلية** | سجل المهارات **عالمي** يُشارك بين المسارات؛ الربط بالدور محلي — وإلا انكسرت هوية المهارة عبر المسارات |
| **DF-7** | **الكمّ ليس هدفًا** | حزمة صغيرة مُراجَعة أثمن من حزمة ضخمة غير مُراجَعة · **التغطية تُقاس بالاستخدام لا بالعدد** |
| **DF-8** | **قابلية التحديث مُصمَّمة لا مُرتجَلة** | كل حزمة مُصدَّرة · الطبقة المنشورة غير قابلة للتعديل · التحديث إصدار جديد لا تعديل مكان |
| **DF-9** | **الأرقام تُقاس ولا تُقدَّر** | أحجام الحزم وأزمنة البناء **فرضيات حتى تُقاس في Phase 0** (D-043b) |
| **DF-10** | **مساعدة AI في الصياغة مسموحة، وفي الاعتماد ممنوعة** | يجوز أن يُصاغ وصف بمساعدة نموذج، **ولا يُنشر بلا اعتماد SME** — ويُسجَّل ذلك صراحة (§5) |

## 2. ما تخدمه هذه البيانات
`Skill Gap Analysis` · `Learning Recommendations` · `Activities` · `Rubrics` · `Evidence` · `CV` · `LinkedIn` · `Career Progress`.

**قاعدة تصميم مشتقة:** كل حقل في الحزمة يجب أن يُجيب عن سؤال: **أي من هذه الثمانية يستهلكه؟** حقل لا يستهلكه أحد **لا يُجمَع**.

## 3. الطبقات الأربع (Raw → Normalized → Curated → Published)

```
L0 RAW          لقطة خام غير معدَّلة من المصدر            [غير قابلة للتعديل · أرشيفية]
L1 NORMALIZED   موحَّدة الشكل واللغة والوحدات              [آلية بالكامل · قابلة لإعادة التوليد]
L2 CURATED      مُطابَقة ومُنقّاة ومربوطة بالمعرّفات الداخلية  [بشرية القرار · مسوّدة قابلة للمراجعة]
L3 PUBLISHED    مُصدَّرة ومُعتمدة من SME · مجمّدة            [ما يستهلكه المنتج فقط]
```

| الطبقة | ما يحدث فيها | من يملكها | قابلية التعديل |
|---|---|---|---|
| **L0 Raw** | حفظ لقطة المصدر كما هي (ملف · صفحة · تصدير) + بيانات الالتقاط (المصدر · التاريخ · الإصدار) · **لا تنظيف ولا ترجمة ولا حذف** | آلي | **غير قابلة للتعديل نهائيًا** — تُحفظ للتدقيق وإعادة الاشتقاق |
| **L1 Normalized** | توحيد الترميز · تنظيف المسافات · فصل الحقول · توحيد الوحدات والتواريخ · تحديد اللغة · تقسيم المهارات المركّبة إلى مرشّحات · **بلا أي قرار دلالي** | آلي بالكامل | قابلة لإعادة التوليد من L0 في أي وقت |
| **L2 Curated** | **القرارات البشرية:** المطابقة بالمعرّفات الداخلية · دمج المترادفات · إزالة التكرار · تحديد النوع والأهمية والمستوى المستهدف · صياغة الأوصاف · اقتراح الموارد | مؤلف المحتوى (R-3 / Content Author) | مسوّدة حيّة — تتغير بحرية قبل النشر |
| **L3 Published** | **حزمة مُصدَّرة معتمدة:** `pack_version` مجمّد · `review_status = approved` · `sme_approval` موجود · manifest موقّع بالإصدارات | SME (اعتماد) + Product Owner (نشر) | **مجمّدة** — التحديث ينشئ إصدارًا جديدًا و`superseded` للقديم |

**قواعد ملزمة بين الطبقات:**
1. **لا يستهلك المنتج إلا L3.** التشخيص والتوصية والتقييم لا يقرأون L0/L1/L2 أبدًا.
2. **كل سجل في L3 يشير إلى أصله في L0** عبر `source_id` + `source_version` + `retrieved_at`.
3. **L1 قابلة لإعادة التوليد بالكامل** — إن لم تكن، فثمة قرار دلالي تسلّل إليها ويجب نقله إلى L2.
4. **تغيير في L0 لا يغيّر L3 آليًا** — يفتح مهمة مراجعة فقط (§6 · §8).

## 4. تصنيف المصادر

| `source_type` | المعنى | أمثلة | يصلح حقيقةً لـ |
|---|---|---|---|
| `official` | مصدر مرجعي رسمي أو معياري | تصنيفات المهن والمهارات الوطنية · ESCO · أطر كفاءات رسمية · توثيق منتج رسمي | متطلبات الدور · تسميات المهارات · الأطر |
| `curated` | محتوى أنتجته المنصة بمراجعة تحريرية وSME | أوصاف الأدوار · الرُبريكات · الأنشطة · تبريرات الترشيح | كل محتوى الحزمة |
| `market_signal` | إشارة سوق **مؤقتة** | تحليل إعلانات وظائف · تقارير سوق · مقابلات مع مشغّلين | **مؤشرات فقط — لا حقيقة دور** |
| `platform_generated` | مُشتق من أداء المستخدمين على المنصة | تكرار رسوب بند رُبريك · صعوبة نشاط فعلية | معايرة الرُبريكات والأنشطة |

**قواعد:**
- **كل حقل في L3 يحمل `source_type` واحدًا على الأقل.**
- `market_signal` **لا يُستخدم وحده** لإثبات متطلب دور (DF-4).
- `platform_generated` **لا يُستخدم قبل بلوغ حجم عيّنة مُعلَن** (يُحدَّد في Phase 0).
- **مصدر بلا ترخيص واضح لا يدخل L0** — `license_notes` إلزامي.

## 5. قواعد المصدر والنسب (Provenance Rules)

كل سجل في L2/L3 يحمل:

| الحقل | إلزامي | المعنى |
|---|---|---|
| `source_type` | ✅ | من تصنيف §4 |
| `source_id` | ✅ | مرجع إلى سجل في `SOURCES.json` |
| `source_version` | ✅ | إصدار المصدر وقت الاشتقاق |
| `retrieved_at` | ✅ (لغير `curated`) | زمن الالتقاط |
| `created_at` · `created_by` | ✅ | من أنشأ السجل |
| `drafting_aid` | ✅ | `none` · `ai_assisted` — **الإفصاح عن مساعدة النموذج في الصياغة** |
| `reviewed_by` | ✅ في L3 | معرّف المراجع/SME |
| `review_status` | ✅ | من دورة §6 |
| `reviewed_at` | ✅ في L3 | زمن الاعتماد |
| `supersedes` · `superseded_by` | حسب الحالة | سلسلة الإصدارات |
| `confidence` | لإشارات السوق | ثقة الإشارة |

**قاعدة `drafting_aid` (DF-10):** محتوى صاغه نموذج لغوي ثم اعتمده SME يُسجَّل بـ`source_type = curated` **و**`drafting_aid = ai_assisted`. **لا يُوسَم `ai_generated`** (لأنه مُراجَع)، **ولا يُدَّعى أنه بشري خالص** (لأنه ليس كذلك).
**وممنوع مطلقًا:** محتوى `drafting_aid = ai_assisted` بلا `reviewed_by` في L3.

## 6. دورة المراجعة (Review Workflow)

```
draft → curated → sme_reviewed → approved → published → superseded
                       ↓
                   rejected / needs_revision  (يعود إلى curated)
```

| الحالة | من يمنحها | الشرط | أثرها |
|---|---|---|---|
| `draft` | Content Author | — | غير مرئي للمنتج |
| `curated` | Content Author | مُطابَق بمعرّفات داخلية · حقول إلزامية مكتملة · مصدر مسجَّل | جاهز للمراجعة |
| `sme_reviewed` | **SME (R-3)** | صحة الموضوع · دقة المستوى المستهدف · واقعية المهام · سلامة الرُبريك وIntegrity Checks | لا يكفي للنشر وحده |
| `approved` | **SME** بشكل صريح | اجتياز بوابات جودة الحزمة (وثيقة 23 §10) | **شرط حاجب لأي نشاط يمنح `Verified`** (D-030 · FR-G-020) |
| `published` | Product Owner (R-1) | حزمة مُصدَّرة + manifest مكتمل | ما يستهلكه المنتج |
| `superseded` | تلقائي بالنشر الأحدث | — | يبقى مقروءًا إلى الأبد للتقييمات القديمة |
| `rejected` / `needs_revision` | SME | مع سبب مكتوب إلزامي | يعود إلى `curated` |

**قواعد ملزمة:**
1. **لا سجل يصل `published` بلا `sme_approval`** — بلا استثناء لأي نشاط أو رُبريك أو فحص نزاهة.
2. **مراجعة SME تُسجَّل في `REVIEW_LOG.json`** بـ: من · ماذا · متى · القرار · السبب · الزمن المستغرق *(الزمن يُقاس لأنه أحد قياسات Phase 0)*.
3. **المراجعة على مستوى السجل لا الحزمة** — اعتماد الحزمة = اعتماد كل سجلاتها الحاجبة.
4. **تعارض المصالح:** إن كان الـSME هو مؤلف السجل، يُسجَّل ذلك صراحة (يُسمح في Phase 0 فقط — D-038).
5. **لا بيانات غير مراجعة تدخل توصيات المستخدم** — قيد بنيوي، لا سياسة.

## 7. الحدّ الفاصل: Structured Data مقابل RAG

> ### **RAG ليس قاعدة الحقيقة. أبدًا.**

### 7.1 يجب أن يكون **Structured** (مصدر حقيقة)
| البيانات | لماذا |
|---|---|
| `skill_id` والمعرّفات كلها | الهوية لا تُستنتج من نص |
| متطلبات الدور والمستويات المستهدفة والأوزان | تُحسب عليها الفجوة |
| `Role ↔ Skill` mapping | أساس التشخيص |
| بنود الرُبريك وأوزانها وعتباتها | INV-2 — لا تقييم بلا رُبريك مُصدَّر |
| Integrity Checks وتوقعاتها | تحدد سقف الادعاء |
| `ActivitySpec` بحقوله | INV-7 |
| المستويات وقوة المصدر والحداثة | INV-9 |
| بيانات موارد التعلّم الوصفية (نوع · لغة · مستوى · مدة · مجاني/مدفوع) | يُرشَّح عليها حتميًا |
| قواعد عرض الأصول المهنية | تمنع ادعاء يتجاوز الدليل |
| `Evidence` · `Claim` · `Evaluation` | نواة المنتج |

### 7.2 يمكن أن يدخل **RAG** (استرجاع للصياغة والسياق)
وثائق المصادر الطويلة · أوصاف أدوار خارجية · نصوص موارد التعلّم · ملاحظات SME النصية · تقارير سوق · توثيق تقني · أمثلة سرد الحالات الدراسية.
**الشرط:** كل مخرَج مبني على استرجاع يُوسَم `ai_generated`، **ولا يدخل L3 بلا مراجعة**.

### 7.3 Hybrid Retrieval (مُهيكَل أولًا ثم استرجاع)
| الحالة | الآلية |
|---|---|
| توصية تعلّم | **فلترة مُهيكَلة** (المهارة · المستوى · اللغة · المدة · مجاني) **ثم** استرجاع لصياغة «لماذا هذا المورد» |
| صياغة Career Snapshot | فجوات محسوبة حتميًا **ثم** صياغة نصية |
| تأليف نشاط جديد | `Role` + `Skills` مُهيكَلة **ثم** استرجاع سياق مهني واقعي كمسوّدة لـSME |
| شرح بند رُبريك للمستخدم | البند مُهيكَل **ثم** شرح مُصاغ |

### 7.4 محظورات صريحة
| ممنوع | السبب |
|---|---|
| حساب فجوة من نص مُسترجَع | الفجوة `system_derived` بقاعدة صريحة |
| اشتقاق بند رُبريك أو عتبة من استرجاع | INV-2 |
| منح مستوى مهارة بناءً على استرجاع | INV-9 |
| تقديم رقم سوق أو نسبة من استرجاع بلا سجل مصدر مُهيكَل | INV-4 |
| إدخال مخرَج استرجاع إلى L3 بلا مراجعة SME | DF-2 · DF-10 |
| ترشيح مورد تعلّم غير موجود في السجل | يفتح باب اختلاق الروابط |

## 8. ما يبقى يدويًا في Phase 0 · وما يُؤتمَت لاحقًا

### 8.1 يدوي إلزامًا في Phase 0
| العمل | لماذا لا يُؤتمَت الآن |
|---|---|
| **اعتماد SME** لكل نشاط ورُبريك وفحص نزاهة | قرار خبرة حاجب (D-030) |
| **قرار تسمية المهارة الداخلية وحدودها** | يحدد هوية دائمة لا تُراجَع لاحقًا بسهولة |
| **الفصل في دمج المترادفات والتكرار** | خطأ الدمج يُفسد التتبّع عبر المسارات |
| **تحديد المستوى المستهدف لكل مهارة في الدور** | حكم سوقي لا نص |
| **ضبط عتبات الرُبريك** | تُشتق من المجموعة الذهبية بحكم بشري |
| **تصميم الأنشطة وIntegrity Checks** | جوهر التمايز ومقاومة الغش |
| **فحص جودة موارد التعلّم** | رابط يعمل ≠ مورد جيد |
| **النشر** | فعل مسؤولية موثّق |

### 8.2 قابل للأتمتة لاحقًا
| العمل | متى |
|---|---|
| التقاط لقطات L0 وأرشفتها | مبكرًا — قيمة فورية |
| التطبيع الكامل L0→L1 | مبكرًا |
| **اقتراح** مرشحات المطابقة والتكرار (لا القرار) | P1–P2 |
| **اقتراح** مترادفات من المصادر | P2 |
| فحص صلاحية الروابط وتحديث `last_checked` | مبكرًا |
| التحقق الآلي من الحقول الإلزامية وبوابات جودة الحزمة | **مبكرًا — أعلى عائد لأقل جهد** |
| إصدار الحزم وmanifest والتتبّع | P1 |
| تقارير تغطية الحزمة (مهارة بلا مورد · بند بلا مهارة · نشاط بلا فحص نزاهة) | **مبكرًا** |
| استيعاب إشارات السوق وتنبيهات التقادم | P4 |
| معايرة الأنشطة من أداء المستخدمين (`platform_generated`) | P2 بعد حجم عيّنة كافٍ |

> **قاعدة الحسم:** **نؤتمت الاتساق، ولا نؤتمت الحكم.**
