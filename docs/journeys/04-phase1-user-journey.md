# الوثيقة 1 — Phase 1 User Journey
> من أول زيارة حتى أول **Verified Skill Evidence**. لا تصميم بصري — الوصف سلوكي ومنطقي فقط.
> يُقرأ مع: `docs/agents/05-master-agent-contract-map.md` · `docs/standards/07-verified-skill-evidence.md` · `docs/standards/08-ai-usage-policy.md`

## اصطلاحات
- **الوكلاء** بمعرّفاتهم من سجل الرؤية (A01…A19). الوكلاء في P1 **يقترحون فقط** (LBD-05).
- **البيانات** تُذكر ككيانات مفاهيمية وأحداث — **ليست Schema**.
- كل خطوة تُصدر حدثًا واحدًا على الأقل إلى Career Event Log (الثابت 8).
- الهدف الزمني للرحلة كاملة: **≤ 10 أيام**، وزمن الجلسة الأولى **≤ 12 دقيقة حتى بدء أول Activity**.

# الجزء الأول — Happy Path (21 خطوة)

### S01 — Landing / الدخول
- **يرى:** وعد واحد صريح ("اخرج بدليل مهارة موثّق، لا بسيرة مجمّلة")، مثال حقيقي لـCase Study، وشرط الالتزام بصراحة (≈ ساعة لأول مهمة).
- **يفعل:** يقرأ، ثم يبدأ.
- **خلف الكواليس:** لا استدعاء نماذج إطلاقًا. صفحة ثابتة.
- **الوكلاء:** لا أحد.
- **البيانات:** `Event: visit.landed` (مجهول، بلا هوية).
- **الفشل:** توقّع خاطئ (يظنه مولّد CV) → تسرّب لاحق مكلف.
- **الرسالة:** "هذه ليست منصة لكتابة السيرة الذاتية. هذه منصة تصنع ما تكتبه فيها."

### S02 — التسجيل
- **يرى:** تسجيل بحقول دنيا + إفصاح صريح عن البيانات المجمّعة والغرض.
- **يفعل:** ينشئ حسابًا ويقبل الموافقات (منفصلة: تشغيل الخدمة / تحسين المنتج / العرض العام لاحقًا).
- **خلف الكواليس:** إنشاء `Person`، ربط `org_id = null` (محجوز — D-006)، إنشاء `ConsentRecord`.
- **الوكلاء:** لا أحد.
- **البيانات:** `Person` · `ConsentRecord` · `Event: account.created`.
- **الفشل:** رفض الموافقة الأساسية → لا يمكن المتابعة (يُقال له بوضوح لماذا). · بريد مكرر. · تسجيل آلي (bots).
- **الرسالة:** "نجمع ما يلزم لبناء دليلك فقط. تستطيع تصدير بياناتك أو حذفها في أي وقت."

### S03 — حجز username *(D-005)*
- **يرى:** طلب اسم مستخدم مع شرح صريح: "هذا سيكون عنوان ملفك المهني العام لاحقًا — احجزه الآن."
- **يفعل:** يختار اسمًا ويتأكد توفره.
- **خلف الكواليس:** حجز في مساحة أسماء عامة دائمة؛ `/u/{username}` **محجوز وغير منشور** حتى P4؛ قواعد منع الانتحال والأسماء المحجوزة.
- **الوكلاء:** لا أحد (تحقق حتمي).
- **البيانات:** `UsernameReservation` · `Event: username.reserved`.
- **الفشل:** الاسم محجوز/مخالف → اقتراحات بديلة. · محاولة انتحال علامة أو شخص → رفض.
- **الرسالة:** "هذا الاسم لك. ملفك العام سيُفعَّل لاحقًا على العنوان نفسه."

### S04 — Onboarding (8–12 حقلًا)
- **يرى:** أسئلة قصيرة: التخصص، سنة التخرج، الوقت الأسبوعي المتاح، اللغة المفضّلة، الأدوات التي يعرفها، تفضيل مجاني/مدفوع.
- **يفعل:** يجيب. لا رفع ملفات إجباري.
- **خلف الكواليس:** كل إجابة تُخزَّن بـ`provenance = user_declared` (الثابت 5) — **وهذا ليس دليلًا** (الثابت 1).
- **الوكلاء:** لا أحد (نموذج حتمي).
- **البيانات:** `CareerProfile` (THIN) · `Event: onboarding.completed`.
- **الفشل:** انسحاب في المنتصف → حفظ جزئي واستئناف. · إجابات متناقضة → تُقبل وتُوسم للتحقق لاحقًا.
- **الرسالة:** "لا تحتاج سيرة ذاتية الآن. نحتاج نقطة البداية فقط."

### S05 — Career Goal (الهدف)
- **يرى:** **دور مرجعي واحد** متاح في P1 (Junior Data Analyst) مع وصف صادق لما يعنيه، وخيار "لست متأكدًا".
- **يفعل:** يختار الهدف أو يعلن عدم يقينه.
- **خلف الكواليس:** ربط بـ`RoleReferenceSpec` (محتوى مُنسّق، `provenance = curated`). "لست متأكدًا" تقود لنفس المسار مع صياغة استكشافية لا التزامية.
- **الوكلاء:** A02 Career Strategist (`THIN` — اختيار حتمي + صياغة واحدة).
- **البيانات:** `Goal` · `Event: goal.set`.
- **الفشل:** هدف خارج المسار المتاح → إفصاح صريح: "لا ندعم هذا المسار بعد" + قائمة انتظار، **لا وعود زائفة**.
- **الرسالة:** "هدفك الآن ليس قرارًا نهائيًا. هو زاوية نقيس منها."

### S06 — المهارات والمشاريع الحالية
- **يرى:** قائمة مهارات المسار (من `RoleReferenceSpec`) لتقييم ذاتي سريع + إمكانية إضافة مشروع سابق (تخرج/شخصي/تطوعي/Freelance).
- **يفعل:** يقيّم نفسه، وقد يضيف `WorkItem` واحدًا أو أكثر.
- **خلف الكواليس:** التقييم الذاتي يُسجَّل كـ`SelfAssessment` بمستوى ثقة **`Observed` فقط** — لا يرقى لدليل. المشروع المُضاف يدخل Project/Evidence Hub بحالة `self_reported`.
- **الوكلاء:** لا أحد (P1) — A03 Technical Mentor مُسجَّل لاحقًا.
- **البيانات:** `SelfAssessment[]` · `WorkItem[]` (`source: personal|graduation|freelance|volunteering`) · `Event: profile.skills_declared` · `Event: workitem.created`.
- **الفشل:** مبالغة في التقييم الذاتي → **لا نصحّحها الآن**؛ الفجوة ستظهر في التقييم لاحقًا. · رفع ملف ضخم/غير مدعوم.
- **الرسالة:** "ما تكتبه هنا نقطة انطلاق، وليس مهارة مُثبتة بعد. الإثبات يأتي من العمل."

### S07 — Career Snapshot (التشخيص)
- **يرى:** صفحة واحدة: أين أنت من الدور المرجعي · أقوى 3 نقاط · أهم 3 فجوات · **الخطوة التالية الواحدة**.
- **يفعل:** يقرأ، ويستطيع الاعتراض على أي بند ("هذا غير دقيق").
- **خلف الكواليس:** حساب حتمي للفجوة (مطلوب الدور − المعلن) ثم صياغة واحدة عبر A02 تمر ببوابة A18؛ كل عبارة موسومة بـ`provenance` وبمصدرها (`curated` للدور، `ai_generated` للصياغة، `user_declared` للمدخلات).
- **الوكلاء:** A02 (`THIN`) → A18 Quality Gate (قواعد) → A19 Orchestrator.
- **البيانات:** `Snapshot` · `Gap[]` · `NextAction` · `Event: snapshot.generated`.
- **الفشل:** تشخيص عام بلا قيمة → يُقاس باعتراض المستخدم. · فشل النموذج → نسخة حتمية مختصرة بلا صياغة (Fallback). · تجاوز الميزانية → نفس الـFallback.
- **الرسالة:** "هذه ليست نتيجة اختبار. هذه نقطة بداية سنعيد قياسها بعد أول عمل حقيقي."

### S08 — تعيين أول Activity
- **يرى:** مهمة واحدة مُختارة (لا متجر مهام): عنوانها، لماذا هي المناسبة له الآن، الزمن المتوقع، ما سيُثبته، **ونمط استخدام AI المسموح** (D-009).
- **يفعل:** يقبلها ويحدد موعدًا ذاتيًا للتسليم.
- **خلف الكواليس:** اختيار حتمي من 3 أنشطة حسب الفجوة الأعلى أولوية؛ إنشاء `WorkItem` من نوع `platform_activity` مرتبط بـ`ActivitySpec@version` (الثابت 7).
- **الوكلاء:** A19 Orchestrator (اختيار حتمي) · A07 L&D (`THIN` — مورد تعلّم واحد إن كانت الفجوة تمنع البدء).
- **البيانات:** `ActivityInstance` · `WorkItem(kind=platform_activity)` · `Deadline` · `Event: activity.assigned`.
- **الفشل:** المهمة أصعب/أسهل من مستواه → مسار "هذه لا تناسبني" ببديل واحد فقط. · رفض كل البدائل → يُحوَّل لمسار تعلّم قصير قبل المهمة.
- **الرسالة:** "مهمة واحدة. ساعة إلى ساعتين. مخرجها دليل يبقى معك."

### S09 — ظهور Personal Career Companion *(D-007)*
- **يرى:** رفيقًا دائمًا في الواجهة يعرف: حالته الآن · مهمته الحالية · خطوته التالية · سبب هذه المهمة.
- **يفعل:** يسأل أسئلة مثل: ماذا أفعل الآن؟ لماذا هذه المهمة؟ ماذا ينقصني؟ ماذا بعد الانتهاء؟
- **خلف الكواليس:** A01 يقرأ **حالة النظام فقط** (Snapshot · Gaps · ActivityInstance · NextAction · Progress) ويشرحها. **لا يخطط، لا يغيّر استراتيجية، لا يقيّم، لا يَعِد بنتيجة.** كل رد يمر ببوابة A18.
- **الوكلاء:** A01 (`THIN`) · A18.
- **البيانات:** `CompanionMessage[]` · `Event: companion.interaction`.
- **الفشل:** سؤال خارج النطاق (وظائف، رواتب، مقابلات) → إفصاح صريح: "هذا ليس متاحًا بعد" (لا اختلاق). · تشجيع مبالغ → **يُمنع بقاعدة**: لا وعد بوظيفة، لا "أنت جاهز"، لا مقارنة بالآخرين. · تعذّر النموذج → ردود حتمية من الحالة مباشرة.
- **الرسالة:** "خطوتك الآن: [إجراء واحد]. سبب اختيارها: [فجوة محددة]."

### S10 — تنفيذ المهمة
- **يرى:** سياق العمل: من العميل/المدير، الملفات، المطلوب، المخرجات المتوقعة، الموعد، وبطاقة **سياسة AI** لهذا النشاط.
- **يفعل:** يعمل — داخل المنصة أو خارجها ثم يرفع.
- **خلف الكواليس:** تتبّع تقدّم خفيف (بدأ/مسودة/مراجعة)، وتسجيل إشارات عملية مُعلَنة مسبقًا (وقت العمل، عدد المسودات) — **بإفصاح، بلا تجسّس** (سياسة AI §5).
- **الوكلاء:** لا أحد أثناء العمل (توفير تكلفة) · A01 عند السؤال.
- **البيانات:** `WorkItem.progress` · `Milestone[]` · `Event: activity.started` · `activity.progressed`.
- **الفشل:** توقّف > 3 أيام → تذكير واحد (S21). · صعوبة تقنية → مورد تعلّم واحد. · ضياع العمل → حفظ تلقائي للمسودة.
- **الرسالة:** "تستطيع استخدام أدوات الذكاء الاصطناعي في هذا النشاط بشرط الإفصاح. ما نقيسه هو حكمك، لا سرعتك."

### S11 — التفاعل مع Virtual Manager
- **يرى:** رسالة أو رسالتين من "المدير": توضيح ناقص، أو تغيير بسيط في المتطلبات، أو سؤال عن سبب قرار.
- **يفعل:** يرد، ويعدّل عمله إن لزم.
- **خلف الكواليس:** A11 يعمل بعدد تدخّلات **محدود ومُسقَّف** من `ActivitySpec`؛ كل تدخّل له غرض تقييمي معلن (قياس التعامل مع الغموض/تغيّر المتطلبات). الردود تُحفظ كجزء من `Submission` وتدخل التقييم السلوكي لاحقًا (P3).
- **الوكلاء:** A11 Virtual Manager (`THIN`) · A19 (يفرض السقف) · A18.
- **البيانات:** `ManagerTurn[]` · `Event: manager.intervened` · `manager.reply_received`.
- **الفشل:** تجاهل المستخدم للرسالة → يُسجَّل كإشارة سلوكية، لا يُعاقَب في P1. · انحراف المدير عن دوره (نصائح تقنية، حلول جاهزة) → **ممنوع بعقد A11**. · تجاوز الميزانية → لا تدخّل إضافي.
- **الرسالة:** "رسالة من مديرك في هذه المهمة." *(بوسم دائم وواضح أن الطرف الآخر نظام، لا إنسان.)*

### S12 — رفع Submission
- **يرى:** نموذج تسليم: الملف/الرابط + ملخص قراراته + **إقرار استخدام AI** (استخدمته؟ في ماذا؟ بأي مستوى؟ هل تحققت من مخرجاته؟).
- **يفعل:** يرفع ويُقر.
- **خلف الكواليس:** إنشاء `Submission` مرتبط بـ`ActivitySpec@version`؛ تسجيل `AIDisclosure`؛ قفل النسخة (immutable) قبل التقييم.
- **الوكلاء:** لا أحد.
- **البيانات:** `Submission` · `AIDisclosure` · `Artifact[]` · `Event: submission.received`.
- **الفشل:** تسليم ناقص → يُقبل ويُقيَّم كما هو (الاكتمال جزء من الرُبريك). · صيغة غير مدعومة. · تسليم بعد الموعد → يُقبل ويُوسم (بلا عقوبة في P1).
- **الرسالة:** "سنقيّم ما سلّمته مقابل معايير مكتوبة ستراها كاملة بعد التقييم."

### S13 — Automatic Checks (الفحوصات الحتمية)
- **يرى:** نتيجة فورية: ما اكتمل وما نقص — **قبل أي تقييم بالذكاء الاصطناعي**.
- **يفعل:** قد يُصحّح ويعيد التسليم مرة واحدة.
- **خلف الكواليس:** فحوصات قابلة للتكرار 100%: وجود المخرجات الإلزامية، صحة الأرقام المرجعية، احترام القيود، اكتشاف **المصائد المزروعة** في بيانات المدخلات (سياسة AI §4).
- **الوكلاء:** لا أحد — كود حتمي (وهذا مقصود: **لا يجوز لنموذج لغوي أن يقرر ما تستطيع قاعدة أن تقرره**).
- **البيانات:** `DeterministicCheckResult[]` · `Event: checks.completed`.
- **الفشل:** الرسوب في فحص إلزامي → **يتوقف المسار قبل استدعاء أي نموذج** (توفير تكلفة + رسالة أوضح للمستخدم). · خطأ في الفحص نفسه → مسار مراجعة بشرية.
- **الرسالة:** "قبل التقييم: هذه العناصر مفقودة. لديك فرصة تصحيح واحدة."

### S14 — Evaluation (التقييم بالرُبريك)
- **يرى:** انتظارًا قصيرًا، ثم نتيجة **بندًا بندًا** مع المبرر والمقتطف الداعم من عمله.
- **يفعل:** يقرأ، ويستطيع الاعتراض.
- **خلف الكواليس:** A13 يقيّم مقابل `Rubric@version` حصرًا (الثابت 2). كل بند: درجة + مبرر + اقتباس + المهارة المرتبطة به (المطابقة معرّفة في `ActivitySpec`). **لا درجة إجمالية بلا بنود.**
- **الوكلاء:** A13 Performance Evaluator · A15 Coach (`THIN` — تغذية راجعة من البنود فقط، بلا خطة).
- **البيانات:** `Evaluation` · `CriterionScore[]` · `Event: evaluation.completed`.
- **الفشل:** تقييم متساهل/متناقض → يُلتقط في S15 وفي عيّنة المراجعة البشرية. · فشل النموذج → إعادة محاولة واحدة ثم **طابور مراجعة بشرية**، ولا يُصدر النظام نتيجة تخمينية أبدًا. · اعتراض المستخدم → مسار مراجعة بشرية موثّق.
- **الرسالة:** "هذه هي المعايير التي قِيس بها عملك، وهذا ما استندنا إليه في كل بند."

### S15 — Verification (بوابة التحقق)
- **يرى:** غالبًا لا شيء — إلا عند خفض مستوى أو رفض ادعاء.
- **يفعل:** لا شيء (خطوة نظام).
- **خلف الكواليس:** A18 يفحص: لا ادعاء بلا دليل · لا تناقض بين البنود والمقتطفات · لا مبالغة في الصياغة · اتساق إقرار AI مع إشارات العملية · تحقق شروط `Verified` السبعة (الوثيقة 07). **قاعدة حاسمة: التحقق يخفض أو يُثبّت، ولا يرفع أبدًا.**
- **الوكلاء:** A18 (قواعد في P1) · مسار `human_review` لعيّنة إلزامية.
- **البيانات:** `VerificationVerdict` · `Event: verification.completed` · `verification.downgraded`.
- **الفشل:** تعارض A13 مع A18 → **يسود A18 نزولًا**، ويُحال إلى مراجعة بشرية. · تعذّر التحقق → الدليل يبقى `Demonstrated` ولا يصل `Verified`.
- **الرسالة:** *(عند الخفض)* "سجّلنا هذا الإنجاز، لكننا لم نعتمده كمهارة موثّقة بعد — والسبب: [سبب محدد]."

### S16 — Evidence Creation (إنشاء الدليل)
- **يرى:** بطاقة دليل: المهارة · المستوى (Observed/Practiced/Demonstrated/Verified) · مصدره · تاريخه · المقتطف الداعم · طريقة التحقق · وسم استخدام AI.
- **يفعل:** يقرأ، ويستطيع إخفاءه من العرض العام (لا حذفه من السجل).
- **خلف الكواليس:** A14 يستخرج `EvidenceProposal` من بنود الرُبريك المرتبطة بالمهارات فقط؛ يمر بـA18؛ يُنشأ `Claim` **مرتبطًا بدليل** (الثابت 1).
- **الوكلاء:** A14 Evidence · A18.
- **البيانات:** `Evidence` · `Claim` · `SkillLevel` · `Event: evidence.created`.
- **الفشل:** لا بند يكفي لإثبات أي مهارة → **لا يُنشأ دليل**، ويُقال ذلك صراحة (هذه نتيجة مشروعة، لا خطأ). · مهارة خارج التصنيف الداخلي → تُسجَّل كـ`unmapped` للمراجعة.
- **الرسالة:** "أثبتّ: [مهارة] — بمستوى [مستوى] — عبر [نشاط] — بتاريخ [تاريخ]."

### S17 — Achievement
- **يرى:** إنجازًا مُسجَّلًا في ملفه مربوطًا بالمشروع والأدلة.
- **يفعل:** يستعرضه.
- **خلف الكواليس:** Achievement Engine يستهلك `evidence.created` + `activity.completed` من سجل الأحداث (لا استدعاء نموذج).
- **الوكلاء:** لا أحد (محرك حتمي).
- **البيانات:** `Achievement` · `Event: achievement.unlocked`.
- **الفشل:** إنجاز بلا دليل → **ممنوع بنيويًا**. · تكرار إنجاز → منع بمفتاح فريد.
- **الرسالة:** "أُضيف إلى سجلك المهني."

### S18 — CV / LinkedIn Output
- **يرى:** عبارة CV مقترحة + اقتراح LinkedIn (Headline/About/Project)، مع إظهار **مصدر كل عبارة** من الدليل.
- **يفعل:** يعدّل، يقبل، ينسخ/يصدّر.
- **خلف الكواليس:** A17 يصوغ من `Evidence` حصرًا — **لا يخترع رقمًا ولا أثرًا ولا مسمًّى**. كل عبارة مرتبطة بمعرّف دليل؛ تمر بـA18 لمنع المبالغة.
- **الوكلاء:** A17 CV & LinkedIn · A18.
- **البيانات:** `Projection(cv_bullet)` · `Projection(linkedin_suggestion)` · `Event: asset.generated` · `asset.exported`.
- **الفشل:** تعديل المستخدم بما يضخّم الادعاء → تحذير واضح + فقدان وسم "مدعوم بدليل" لتلك العبارة. · لا دليل كافٍ → لا عبارة (بدل عبارة فارغة المعنى).
- **الرسالة:** "كل عبارة هنا مبنية على دليل تستطيع فتحه. تعديلك خارج الدليل يلغي توثيقه."

### S19 — Case Study
- **يرى:** صفحة حالة دراسية جاهزة: السياق · المشكلة · ما فعله · القرارات · النتيجة · المهارات المُثبتة — برابط قابل للمشاركة.
- **يفعل:** يراجع، ينشر أو يبقيها خاصة، ثم يشارك الرابط.
- **خلف الكواليس:** A16 يبني من `WorkItem` + `Submission` + `Evaluation` + `Evidence`؛ النشر يخضع لموافقة العرض العام (S02)؛ الرابط مستقل ولا يفتح `/u/{username}` بعد (P4).
- **الوكلاء:** A16 Portfolio · A18.
- **البيانات:** `Projection(case_study)` · `PublishState` · `Event: case_study.published` · `case_study.shared`.
- **الفشل:** بيانات حساسة داخل المخرجات → فحص قبل النشر + تنبيه. · نشر بلا موافقة → **ممنوع**. · رابط مكسور بعد تعديل → إصدارات محفوظة.
- **الرسالة:** "هذه أول قطعة في ملفك. تستطيع مشاركتها الآن."

### S20 — Project / Evidence Hub Update *(D-008)*
- **يرى:** مشروعه في Hub: العنوان · النوع · المصدر · الحالة · التقدّم · المعالم · الملفات/الروابط · المهارات المرتبطة · الأدلة · الإنجاز.
- **يفعل:** يستعرض، ويستطيع إضافة مشروع خارجي بنفس البنية.
- **خلف الكواليس:** كل الأنواع (`personal` · `graduation` · `freelance` · `volunteering` · `platform_activity`) **كيان واحد بحقل `source`** (LBD-03 وC04). الفرق بينها ليس في البنية بل في **قوة الدليل** (الوثيقة 07 §5).
- **الوكلاء:** لا أحد.
- **البيانات:** `WorkItem` محدَّث · `Event: workitem.completed`.
- **الفشل:** مشروع خارجي بلا تحقق → يبقى `self_reported` ولا يصل `Verified` أبدًا، ويُقال ذلك صراحة. · تضارب مهارات مُعلنة مع مُثبتة → تُعرض المُثبتة أولًا.
- **الرسالة:** "سلسلتك مكتملة: مشروع ← تقدّم ← دليل ← مهارة ← إنجاز ← ملفك المهني."

### S21 — Next Action
- **يرى:** إجراءً واحدًا فقط: النشاط التالي المستهدف لأعلى فجوة متبقية، أو مورد تعلّم إن كانت الفجوة تمنع التقدم.
- **يفعل:** يبدأ الدورة الثانية.
- **خلف الكواليس:** إعادة حساب الفجوات **ببيانات الأداء الحقيقية** لا بالتقييم الذاتي؛ A01 يحوّلها إلى إجراء واحد؛ جدولة تذكير واحد عند التوقف.
- **الوكلاء:** A19 · A01 (`THIN`) · A07 (`THIN`).
- **البيانات:** `Gap[]` محدَّثة · `NextAction` · `Event: next_action.proposed` · `nudge.scheduled`.
- **الفشل:** لا نشاط مناسب متبقٍ (3 أنشطة فقط في P1) → إفصاح صريح + قائمة انتظار للمسار التالي، **لا تكرار للمهمة نفسها**. · تجاهل التذكير مرتين → يتوقف التذكير (لا مطاردة).
- **الرسالة:** "خطوتك التالية: [إجراء واحد]. السبب: أداؤك أظهر فجوة في [مهارة]."

# الجزء الثاني — أهم Edge Cases

| # | الحالة | السلوك المعتمد |
|---|---|---|
| E01 | يسجّل ولا يبدأ أي نشاط | تذكيران بحد أقصى خلال 7 أيام، ثم توقّف. لا استدعاء نماذج. |
| E02 | يبدأ النشاط ولا يسلّم (التسرّب الأخطر) | تذكير عند اليوم 3، وعرض "تقليص النطاق" (تسليم جزئي مقبول ويُقيَّم كما هو). |
| E03 | يسلّم عملًا ضعيفًا جدًا | تقييم صادق + دليل بمستوى `Practiced` لا `Verified` + خطوة تصحيح واحدة. **لا تضخيم للمجاملة.** |
| E04 | يعترض على التقييم | مسار اعتراض موثّق → مراجعة بشرية → قرار نهائي مُعلَّل. يُسجَّل كمقياس جودة. |
| E05 | يسلّم مخرج AI خامًا | الفحوصات الحتمية + المصائد المزروعة + سؤال التبرير. النتيجة: لا يصل `Verified`، مع رسالة غير اتهامية (سياسة AI §6). |
| E06 | يقر باستخدام AI لكل شيء | **مقبول تمامًا** في نشاط `ai_expected`؛ يتغير محتوى الادعاء إلى "حكم وتحقق" لا "إنتاج" (الوثيقة 07 §8). |
| E07 | ينكر استخدام AI وتناقضه الإشارات | لا اتهام ولا عقوبة آلية → سؤال تبرير إضافي، ثم حجب `Verified` فقط. مراجعة بشرية قبل أي أثر دائم. |
| E08 | يضيف مشروعًا خارجيًا ويطلب توثيقه | يبقى `self_reported`؛ يُعرض عليه نشاط تحقق قصير يرفعه إلى `Demonstrated`. |
| E09 | فشل نموذج / انقطاع خدمة | مسار حتمي بديل لكل خطوة؛ التقييم **لا يُخمَّن** أبدًا → طابور مراجعة. |
| E10 | تجاوز سقف الميزانية (مستخدم أو نظام) | إيقاف الاستدعاءات غير الجوهرية (Companion، تدخلات المدير) وإبقاء التقييم؛ إشعار داخلي فوري. |
| E11 | محتوى غير لائق أو بيانات شخصية لطرف ثالث في التسليم | فحص قبل النشر؛ منع النشر العام؛ لا يمنع التقييم الخاص. |
| E12 | طلب حذف الحساب | حذف/إخفاء البيانات الشخصية مع الاحتفاظ بسجل أحداث مجهول الهوية للمعايرة (مُعلَن في الموافقة). |
| E13 | يطلب مسارًا غير مدعوم | إفصاح صريح + قائمة انتظار. **لا توليد مسار وهمي.** |
| E14 | يسأل Companion "هل سأحصل على وظيفة؟" | إجابة صريحة: لا نتنبأ بالتوظيف؛ نعرض ما أثبته وما ينقصه فقط. |
| E15 | يكمل الأنشطة الثلاثة كلها | إعلان صادق بأن المسار انتهى في هذه المرحلة + دعوة لملف الانتظار. **لا حشو.** |
