# مسار مطوّر/ة واجهات ويب — مبتدئ: حزمة المعايرة وقرارات ما قبل P6

**إلى:** خبير المراجعة (SME-JFE-01) · **من:** مالكة المنتج · **التاريخ:** 2026-10-18 · **المراجعة ٢ (D-128):** حُذف كل سؤال سبق أن أجبتم عنه. لا تطلب هذه الحزمة إلا قيم المعايرة التي لم تُحدَّد بعد.

**ما أجبتم عنه ولا يُعاد سؤالكم فيه:**
- لا يوجد شرط عام بمشروعين أو مهمتين لكل مهارة. الأدلة تُصمَّم لكل مهارة على حدة بحسب جدولكم (C3، F3).
- يكفي مشروع واحد متحقَّق منه لإثبات Git (F4).
- الجاهزية تعني: كل مهارات Must بالمستوى المطلوب، والحد الأدنى لكل مهارة Core، واجتياز المهمة المتكاملة (C5).
- العبرة بالتطبيق العملي المستقل، لا بعدد الملفات أو المهارات (C3، SME-16، SME-54).
- يجوز التقييم الآلي بمعايير معتمدة ومعايَرة، مع مراجعة بشرية للحالات الاستثنائية (C4).
- تصنيف المهارات، والمستوى المبتدئ لكل مهارة، والحد الأدنى لعدد المهام لكل مهارة (جدولكم)، وقراءة الكود، وفهم الكود للجميع، والأنشطة الثلاثة (F1–F5).

**طريقة الإجابة:** لكل بند **موافق / تعديل (مع ملاحظة) / رفض**، أو قيمة صريحة حيث يُطلب ذلك. البنود المؤشَّرة **(قرار مهني)** لا يملؤها أحد غيركم.

## ١. عتبات التقييم لكل مهارة

لكل مهارة نتيجة مستقلة في كل تقييم، تُحسب **من معاييرها هي فقط**: «مستوفاة» أو «غير مستوفاة». العتبة هي الحد الأدنى من درجة المعيار الذي يُعدّ به المعيار مستوفًى لتلك المهارة.

## ٢. مستوى التحقق المطلوب للجاهزية

**محسوم ولا يُعاد السؤال فيه:** متطلبات الأدلة لكل مهارة (جدولكم ومسارات الأدلة).

**التصميم المعتمد مؤقتًا من مالكة المنتج (L-1):**
- متطلبات منح المستوى ومتطلبات الجاهزية منفصلة، ويمكن ضبط كل منهما وحده.
- هذا لا يعني اعتماد أي عتبة لمستوى Demonstrated. العتبات تبقى قيمكم في البند ١.

**قيمة معايرة واحدة باقية (DM-2، مع مالكة المنتج):** ما المستوى الذي تقرؤه قاعدة الجاهزية؟

| الخيار | المعنى |
|---|---|
| V-a | Demonstrated لمهارات Must وCore |
| V-b | Demonstrated لـMust، وPracticed لـCore |
| V-c | تأجيل القرار |

- **ملاحظة:** لا يوجد اليوم نشاط يمنح Practiced.

## ٣. قاعدة اجتياز المهمة المتكاملة

| البند | الخيارات | إجابتكم **(قرار مهني)** |
|---|---|---|
| القاعدة | **PR-2:** البوابة + كل المعايير الإلزامية · **PR-1:** PR-2 + مجموع كلي لا يقل عن عتبة معتمدة | |
| المعايير الإلزامية | المقترح في الحزمة ٠٩: المعايير ١–٨ إلزامية، و٩–١١ غير إلزامية، و١٢ بوابة | |
| عتبة المجموع (إن اخترتم PR-1) | تبقى فارغة حتى تحدّدوها. لا تُفترض أي قيمة | |
| المنطقة القريبة من الحد | النتائج التي تُحال إلى مراجعة بشرية: ما حدودها؟ | |

**ما يضمنه النظام أيًّا كانت إجابتكم:**
- النتيجة التي تنتظر مراجعة بشرية لا تُعدّ اجتيازًا.
- سحب الدليل («ليس عملي») يُلغي الاجتياز.
- لا يُحسب الاجتياز إلا على نسخة نشاط ومعايير معتمدة ومثبّتة.
- إنجاز النشاط شيء، والاجتياز شيء آخر، والجاهزية شيء ثالث.
- نتائج المهارات داخل المهمة المتكاملة تُعرض لكل مهارة على حدة ولا تُدمج.

## ٤. استثناء المهمة الواحدة: Git وAccessibility

| المهارة | المسار المقترح | ما يُطلب تأكيده **(قرار مهني)** |
|---|---|---|
| Git (Must) | مشروع واحد (المتكاملة، المعيار ٨): فرع، وإيداعات صغيرة موصوفة، وPull Request بوصف، وشرح أسطر محددة. يسجّل المراجع رمز الإيداع الذي راجعه | هل «إيداعان موصوفان على الأقل» حد أدنى مناسب؟ وما الحد الأدنى لوصف الـPR؟ |
| Accessibility (Core) | مهمة واحدة عملية (عدد المهام محسوم منكم): (أ) ٢، ويُقبل بديلًا المعيار ١١ من المتكاملة | تأكيد صياغة المسار فقط (البند S5): أي المعيارين يُحتسب |

- **مؤكَّد منكم سابقًا (F4):** الرابط وحده دون فحص لا يُعدّ دليلًا. أي اختلاف بين الرمز المعلن والرمز المراجَع يُحال إلى المراجعة، ولا يُعدّ اتهامًا.

**شروط الاستقلالية (مطبَّقة هندسيًا):**
- مهمتان من **عائلتين مختلفتين**: المتكاملة، و(أ)، و(ب) ثلاث عائلات.
- إعادة النشاط نفسه أو إعادة تقييمه لا تُحتسب مرتين.
- الملف أو النص المعاد استخدامه بين مهمتين لا يُحتسب. المقارنة **حرفية** بعد توحيد الشكل فقط (التشكيل، والتطويل، والمسافات، والأرقام، وحالة الأحرف).
- لا قياس «تشابه»، ولا كشف «محتوى ذكاء اصطناعي»، ولا اتهام.

**سؤال ٥-١:** هل المهام الثلاث مختلفة بما يكفي ألا يجتاز الحلّ نفسه مهمتين، خصوصًا حالات API في المتكاملة (بناء) مقابل (ب) (تشخيص)؟ **(قرار مهني)**

**سؤال ٥-٢:** هل المصفوفة أعلاه نهائية؟ **(موافق / تعديل)**

## ٦. تسليمات مرجعية ومعايرة المراجعين

لا يوجد بعدُ أي تسليم مرجعي ولا جلسة معايرة. نقترح البروتوكول التالي، **والقيم كلها لكم:**

| البند | المقترح | قيمتكم **(قرار مهني)** |
|---|---|---|
| التسليمات المرجعية | لكل معيار ولكل مستوى من مستوياته (مثل missing / partial / solid) تسليم مرجعي واحد على الأقل، مع تعليل مكتوب لسبب المستوى | عدد التسليمات لكل مستوى: |
| من يُعدّها | أنتم، أو مراجع تسمّونه، من تسليمات تجريبية **غير حقيقية** أو من بيانات بإذن صريح | |
| تدريب المراجعين | كل مراجع يقيّم التسليمات المرجعية دون رؤية مستواها قبل أن يُمنح صلاحية المراجعة | |
| نسبة الاتفاق المطلوبة | بين تقييم المراجع والمستوى المرجعي | النسبة: |
| المراجعة المزدوجة العمياء | عيّنة من التسليمات الحقيقية يراجعها مراجعان دون أن يرى أحدهما تقييم الآخر | حجم العيّنة: |
| عند الاختلاف | يُحال إلى مراجع ثالث، أو إليكم | |
| إعادة المعايرة | متى تُعاد (مثلًا عند تغيير المعايير أو كل فترة) | |

- **ملاحظة:** تُخفى عن المراجع هوية المتقدم وصورته وجامعته وجهة عمله السابقة (SME-27، مطبَّق).

**قرارات لمالكة المنتج وحدها (لا تُطلب منكم):**
- هل يجوز أن تُقترح عبارة في السيرة الذاتية أو LinkedIn بعد بلوغ المستوى وقبل الجاهزية؟
- هل يجوز للدليل الداعم أن يدعم أي عبارة؟ (اليوم: لا)
- هل تُحتسب نتائج التقييم القديمة؟ (اليوم: لا، افتراضيًا)
- تفعيل P6.

**ملاحظة أخيرة:**
- موافقتكم المهنية لا تنشر المحتوى ولا تفعّل أي إعداد.
- قواعد الجاهزية ستبقى مختومة وغير مفعّلة حتى قرار P6 المنفصل من مالكة المنتج، ثم التحقق في بيئة الاختبار.
