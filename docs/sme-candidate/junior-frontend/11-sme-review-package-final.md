## ثانيًا: الأنشطة الثلاثة كما ستُقدَّم

### النشاط ١ — المهمة المتكاملة: صفحة طلبات الإجازة

**المدة المقترحة:** ~150 دقيقة (للتأكيد). **تُعدّ «المشروع»** في نموذج «مشروع + مهمة قصيرة مستقلة».

#### نص المهمة كما يراه المتقدم

> يريد فريق الموارد البشرية صفحة يرى فيها الموظف طلبات إجازته السابقة، تُجلب من خدمة داخلية. بدأ زميل العمل على الصفحة ثم انتقل إلى مهمة أخرى، وترك بلاغًا: «بعد فشل التحميل والضغط على إعادة المحاولة، تظهر الطلبات لكن مؤشر التحميل لا يختفي».
> 1. ابني الصفحة ببنية دلالية، واجعليها مقروءة على الجوال والحاسوب دون تمرير أفقي.
> 2. اعرضي حالات البيانات كلها: جارٍ التحميل، وخطأ مع إمكانية إعادة المحاولة، ولا طلبات، والطلبات.
> 3. حدّدي أين سبب البلاغ في الكود المُقدَّم ولماذا أنتج هذا العَرَض، ثم أصلحيه من سببه.
> 4. اشرحي في ملاحظة قصيرة، بالإشارة إلى كودك، أين تُحفظ الحالة وكيف تصل البيانات إلى الشاشة.
> 5. اذكري قرارين اتخذتِهما ولماذا، وإن وجدتِ تعارضًا بين الوصف والبيانات فاذكريه وما قرّرتِه.
> 6. اعملي على فرع، بإيداعات صغيرة موصوفة، وقدّمي Pull Request يشرح ما تغيّر ولماذا. أرسلي رابطه ورمز آخر إيداع، واشرحي أهم ما غيّرتِه بالإشارة إلى أسطر محددة.
>
> استخدام أدوات الذكاء الاصطناعي مسموح، والإفصاح عنه سياق للمراجعة ولا يؤثر في النتيجة.

#### للمراجع فقط (لا يراه المتقدم)

- **العطل المزروع:** يُعاد ضبط `isLoading` عند إعادة المحاولة لكنه لا يُلغى إلا في فرع نجاح التحميل الأول.
  - **يُحتسب:** الإصلاح في مسار مشترك للنجاح والفشل.
  - **لا يُحتسب:** إخفاء المؤشر بـCSS أو حذفه.
- **تعارض مقصود:** بين الوصف والبيانات في ترتيب الطلبات.
- **الخدمة التجريبية تُعيد:** قائمة · خطأ 500 · قائمة فارغة · استجابة بطيئة.

### النشاط ٢ — مهمة قصيرة (أ): صفحة التسجيل في الورشة

**المدة المقترحة:** ~60 دقيقة (للتأكيد). **مهمة تحقّق مستقلة.**

#### نص المهمة كما يراه المتقدم

> صفحة «تسجيل في ورشة» قائمة تلقّت شكاوى: تنكسر على الجوال، ولا تعمل بلوحة المفاتيح، وتقبل بريدًا غير صالح. مسؤولة التسويق تريد إطلاقها خلال يومين.
> أصلحي البنية الدلالية وإتاحة النموذج (تسميات واضحة، ورسائل خطأ مرتبطة بحقولها، واستخدام كامل بلوحة المفاتيح مع تركيز ظاهر)، والسلوك المتجاوب، والتحقق من البريد، دون إعادة كتابة الصفحة.
> اكتبي لكل عطل سطرًا يسمّي سببه لا عَرَضه، وأجيبي: إحدى الشكاوى تقول «الزر لا يعمل»؛ ما السبب الفعلي الذي وجدتِه، وكيف تأكدتِ؟

#### للمراجع فقط

**الأعطال المزروعة:**
- قاعدة `overflow-x: hidden` تُخفي عطل العرض الحقيقي؛
- «الزر لا يعمل» سببه التركيز أو المعالج لا الزر؛
- البريد يُقبل دون تحقق؛
- عناصر تحكم غير دلالية.

## ثالثًا: مسار الأدلة لكل مهارة

- عدد المهام لكل مهارة **محسوم منكم**.
- المطلوب فقط تأكيد **صياغة المسار**: أي المعايير تُحتسب، وفي أي مهمة.

| المهارة | التصنيف | عدد المهام العملية المختلفة | ما يُحتسب | عنصر الفهم |
|---|---|---|---|---|
| HTML | Must | ٢ | المتكاملة ١ + (أ) ١ | فهم الكود في المتكاملة |
| CSS | Must | ٢ | المتكاملة ٢ + (أ) ٣ | فهم الكود في المتكاملة |
| JavaScript | Must | ٢ | (أ) ٤ + (ب) ٦ | فهم الكود في المتكاملة (معيار ٧) |
| Debugging | Must | ٢ | المتكاملة ٦ + (ب) ٣ (أو (أ) ٥) | ضمن المعيار |
| قراءة الكود | Must | ٢ | المتكاملة ٥ + (ب) ١ **و** ٢ | ضمن المعيار |
| Git | Must | **١** | المتكاملة ٨ | شرح التغييرات ضمن المعيار |
| UI State | Core | ٢ | المتكاملة ٤ + (ب) ٤ | فهم الكود في المتكاملة |
| API States | Core | ٢ | المتكاملة ٣ + (ب) ٥ | فهم الكود في المتكاملة |
| Accessibility | Core | ١ | (أ) ٢ (أو المتكاملة ١١) | فهم الكود في المتكاملة |

**عن الاستقلالية:**
- لا تُحتسب محاولتان للنشاط نفسه دليلين.
- لا يُحتسب ملف مُعاد استخدامه بين مهمتين.
- لا تُستنتج مصادر العمل ولا تُعطى «درجة غش».

## رابعًا: طريقة المعايرة المقترحة (الأرقام لكم)

1. **جلسة معايرة أولى** مع مالكة المنتج:
   - لكل معيار: الأوزان، والعتبة لكل مهارة، ووصف كل مستوى (missing / partial / solid، أو unmet / met)، بحسب الحدّ المبتدئ (Working أو Familiar).
   - **قاعدة تمثيل ثابتة:** تُقبل العتبة فقط إن كانت درجةً يمكن بلوغها بمستويات المعيار.
2. **تسليمات مرجعية**:
   - لكل معيار ولكل مستوى تسليم مرجعي واحد على الأقل، مع تعليل مكتوب.
   - تُعدّ من تسليمات تجريبية غير حقيقية، أو من بيانات بإذن صريح.
3. **تدريب المراجعين:**
   - كل مراجع يقيّم التسليمات المرجعية دون رؤية مستواها.
   - لا يُمنح صلاحية المراجعة إلا إذا بلغ نسبة الاتفاق المعتمدة.
4. **مراجعة مزدوجة عمياء** لعيّنة من التسليمات في التجربة، وإحالة الخلاف إلى مراجع ثالث أو إليكم.
5. **محفّزات الإحالة البشرية** قبل أي تقييم آلي (C4): المنطقة القريبة من الحد، والإشارات المتعارضة، والنتيجة الغامضة، وعيّنة معايرة.
6. **إعادة المعايرة** عند تغيير أي معيار أو نسخة نشاط.

**ثابت في النظام:**
- تُخفى هوية المتقدم عن المراجع (SME-27).
- لا قياس تشابه، ولا كشف «محتوى ذكاء اصطناعي»، ولا اتهام.
