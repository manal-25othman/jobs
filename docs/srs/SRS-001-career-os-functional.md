# 1. المقدمة

## 1.1 الغرض
تحديد **المتطلبات الوظيفية وغير الوظيفية** لمنصة Career OS، بصيغة قابلة للتتبّع والاختبار، مع فصل صريح بين ما يُبنى في Phase 1 وما هو محفوظ للمراحل اللاحقة.

## 1.2 نطاق المنتج
Career OS نظام تشغيل مهني مدعوم بالذكاء الاصطناعي للخريجين والباحثين عن أول وظيفة، يحوّل الجهد غير الموجّه إلى **أدلة مهارة موثّقة (Verified Skill Evidence)**: يشخّص وضع المستخدم مقابل دور مهني مرجعي، يسند إليه عملًا واقعيًا، يقيّمه برُبريك مُصدَّر وفحوصات موضوعية، ثم يحوّل كل إنجاز مُثبت إلى مهارة موثّقة وأصول مهنية (CV · LinkedIn · Portfolio · Case Study).

## 1.3 مبدأ الهوية *(D-027 — ملزم على هذه الوثيقة بأكملها)*
> **`Career OS is multi-discipline by design.`**
> `Data Analyst / BI` **مسار تحقق أول (validation beachhead)، وليس هوية المنتج.**
> **لا يجوز لأي متطلب في هذه الوثيقة أن يفترض أن المنتج خاص بتحليل البيانات.** المسار **معطى محتوى**، لا افتراض بنيوي.

## 1.4 اصطلاحات الوثيقة
- **MUST** = إلزامي في المرحلة المذكورة · **SHOULD** = مرغوب، يُنفَّذ بعد اكتمال كل MUST.
- **TBD** = لم يُحسم بعد، ومسجَّل في سجل القرارات المفتوحة. **لا تُملأ بأرقام مُخترعة.**
- كل متطلب يحمل: معرّفًا · نصًّا · أولوية · مرحلة · مصدرًا (ميزة/قدرة) · معيار قبول.
- **معرّفات المتطلبات:** `FR-U` واجهة مستخدم · `FR-P` بنية داخلية · `FR-A` وكيلي · `FR-G` حوكمة · `BR` قاعدة عمل · `DR` بيانات · `SR` حالات · `ER` أحداث · `XR` قابلية توسع · `NFR` غير وظيفي.

# 2. نظرة عامة على المنتج

## 2.1 المشكلة
**فجوة الإثبات:** السوق يطلب خبرة، والخريج بلا خبرة، والشهادات تثبت الحضور لا القدرة. **وفجوة التوجيه:** لا يعرف المسار ولا الفجوة ولا الخطوة التالية.

## 2.2 عرض القيمة
خبرة قبل الوظيفة، ودليل بدل الادعاء. المنصة **طبقة الإثبات (Proof Layer)** بين التعليم والتوظيف — ليست منصة تعليم ولا منصة توظيف.

## 2.3 الحلقة الجوهرية
```
تشخيص → نشاط واقعي → تسليم → فحوص حتمية → Integrity Checks → تقييم برُبريك
      → استخراج دليل → تحقق → حساب مستوى المهارة → إنجاز → أصول مهنية → الإجراء التالي
```

## 2.4 المراحل
| المرحلة | الاسم | الحالة |
|---|---|---|
| P0 | التحقق اليدوي | **معتمد التنفيذ** (D-026) — بالتوازي مع هذه الوثيقة |
| P1 | The Proof Loop | **نطاق هذه الوثيقة التنفيذي** |
| P2 | The Development Loop | محفوظ ومُعرَّف |
| P3 | The Readiness Loop | محفوظ ومُعرَّف |
| P4 | The Market Loop | محفوظ ومُعرَّف |
| P5 | The Growth Loop | محفوظ ومُعرَّف |

## 2.5 المبادئ التشغيلية (الثوابت التسعة) — **تسري على كل متطلب في هذه الوثيقة**
| # | الثابت |
|---|---|
| INV-1 | لا `Claim` بلا `Evidence` |
| INV-2 | لا `Evaluation` بلا `rubric_version` مُصدَّر |
| INV-3 | لا وكيل يكتب في Career Graph — اقتراحات فقط تمر ببوابة |
| INV-4 | لا معلومة سوقية بلا مصدر |
| INV-5 | كل حقيقة تحمل `provenance` |
| INV-6 | كل استدعاء نموذج يمر بالبوابة ويُقاس |
| INV-7 | كل `Activity` يشير إلى `Spec` مُصدَّر |
| INV-8 | كل فعل ذي معنى يُنشر كحدث |
| INV-9 | **`Activity Score ≠ Skill Verification Level`** |

> **خرق أي ثابت يُعد عيبًا حاجبًا (blocking defect)، لا تحسينًا مؤجّلًا.**

# 3. النطاق

## 3.1 نطاق Phase 1 (التنفيذي)
**حلقة إثبات واحدة، لمسار واحد، تنتج دليلًا واحدًا موثّقًا.**
- مسار واحد مُفعَّل: `Data Analyst / BI` (TRK-05/06) — **بوصفه مسار تحقق** (D-027).
- **3 أنشطة** بملف `mission` فقط، كل منها مراجَع من Subject Matter Expert (D-030).
- 91 بندًا وظيفيًا مصنّفة أربع فئات (§5).
- **هدف المستخدم:** من لا شيء إلى **Verified Skill Evidence واحد + Case Study قابلة للمشاركة خلال ≤ 10 أيام.**

## 3.2 خارج نطاق Phase 1 — **محفوظ لا محذوف**
مطابقة الفرص (P4) · ذكاء السوق (P4) · محاكاة المقابلات (P3) · المحاكاة الكاملة متعددة الأطراف (P3) · خطة 30/60/90 (P2) · Project Hub الكامل (P2) · CV Builder الكامل (P2) · Portfolio متعدد المشاريع والموقع الشخصي المنشور (P4) · مسار ريادة الأعمال (P5) · Career Gym (P4–P5) · نظام التنبيهات الكامل (P5) · لوحة المؤسسات (P5) · استيراد ESCO/التصنيف الوطني (P2) · **22 مسارًا مسجّلًا غير مُفعَّل**.

## 3.3 قاعدة التجميد
أي إضافة إلى MUST تتطلب **إخراج بند مكافئ**. وأي بند جديد يُسجَّل في سجل الرؤية أولًا بحالة ومرحلة ونقطة تمديد.

# 4. الفاعلون والأدوار

| الفاعل | الوصف | Phase |
|---|---|---|
| **User** | الخريج/الباحث عن أول وظيفة — مالك بياناته | P1 |
| **Human Reviewer** | مراجع بشري مؤهل — **الطرف الوحيد الذي يرفع مستوى مهارة** | P1 |
| **Content / Activity Author** | مؤلف الأنشطة والرُبريكات والأدوار والموارد | P1 |
| **Subject Matter Expert (SME)** | خبير الموضوع الذي يعتمد النشاط والرُبريك وIntegrity Checks (D-030) | P1 |
| **Platform Admin** | تشغيل ودعم وامتثال — **بلا أي صلاحية تقييمية** (D-036) | P1 |
| **System / Agents** | الخدمات والوكلاء A01–A19 — **اقتراح فقط** | P1 |
| **Organization Admin** | مسؤول جهة في B2B2C | P5 |
| **Employer / Reviewer of Evidence** | مسؤول توظيف يفحص دليلًا منشورًا (قارئ خارجي، بلا حساب) | P1 (قراءة) · P4 (تفاعل) |

**تقييد صريح على Platform Admin (D-036) — لا يستطيع:** رفع أو خفض `Skill Level` · تعديل `Evaluation Score` · إنشاء `Evidence` · حذف `Evidence` لتغيير نتيجة · تجاوز `Rubric` · منح `Verified`.
**قراءة عمل المستخدم** تتطلب سبب دعم موثّقًا وحدث تدقيق.

# 7. قواعد العمل (Business Rules)

| ID | القاعدة |
|---|---|
| BR-001 | التقييم الذاتي لا يُنتج إلا `Observed`، ولا يُعرض علنًا أبدًا |
| BR-002 | الترقية بين المستويات **بعمل جديد فقط** — لا بتكرار التصريح ولا بمرور الوقت ولا بطلب المستخدم |
| BR-003 | بوابة التحقق **تخفض أو تثبّت ولا ترفع**؛ والمراجع البشري وحده يرفع بتوثيق |
| BR-004 | الفحص الحتمي **يسود** على الرُبريك عند التعارض |
| BR-005 | عند تعذّر الحسم ⇒ **المستوى الأدنى** مع شرح غير عقابي |
| BR-006 | `Evidence` لا يُحذف ولا ينتهي؛ **المهارة** هي التي تتقادم |
| BR-007 | الإنجاز مستحيل بلا دليل داعم |
| BR-008 | لغة العرض لا تتجاوز مستوى الدليل؛ وتعديل المستخدم خارج الدليل يُسقط وسم التوثيق |
| BR-009 | الإفصاح عن استخدام AI **لا يخفض الدرجة بذاته**؛ التناقض مع الإشارات هو ما يؤثر على مستوى التوثيق |
| BR-010 | لا يُتخذ أي أثر على مستوى الدليل بناءً على **إشارة نزاهة واحدة** — الحد الأدنى إشارتان مستقلتان |
| BR-011 | نشاط `ai_prohibited` غير قابل للتحقق ⇒ يُحوَّل إلى `ai_assisted` ويُعاد تصميم رُبريكه |
| BR-012 | المهارة الأساسية تتطلب **دليلين مستقلين** — والاستثناء موثّق ومراجَع بشريًا |
| BR-013 | "دليلان مستقلان" = اختلاف `ActivitySpec` **و** اختلاف الجلسة **و** ليس أحدهما إعادة تسليم للآخر |
| BR-014 | `self_reported` لا يبلغ `Verified`؛ والترقية عبر **Validation Activity قصيرة** لا بإعادة المشروع |
| BR-015 | لا يُستدعى نموذج قبل اجتياز التحقق الشكلي والفحوص الحتمية |
| BR-016 | الخط الحرج (تحقق → فحوص → تقييم → دليل → تحقق → مستوى) **لا يُخفَّض لتوفير التكلفة أبدًا** |

| BR-018 | **يُمنع تسويق `Verified` بوصفه معترفًا به من أصحاب العمل قبل وجود دليل ميداني** (D-034) |

# 8. متطلبات الدليل والتقييم

## 8.1 تعريف `Verified Skill Evidence`
ادعاء مهارة **محدود النطاق ومؤرَّخ**، ناتج عن عمل فعلي أنتجه المستخدم، قِيس مقابل رُبريك مُصدَّر، اجتاز فحوصات حتمية وبوابة تحقق، ومرتبط بمقتطف قابل للفتح، ومصحوب بإفصاح عن أي مساعدة من الذكاء الاصطناعي.

## 8.2 المستويات والأبعاد
**المستوى:** `Observed` (داخلي) → `Practiced` → `Demonstrated` → `Verified` → `Verified (Aging)` → `Verified (Historical)`
**قوة المصدر:** `platform_controlled` · `platform_observed` (سقف `Verified`) — `self_reported` · `third_party_asserted` (سقف `Demonstrated`)
**الثقة:** `high` · `medium` · `low` (لا يبلغ `Verified`)

## 8.3 شروط `Verified` الثمانية
| # | الشرط |
|---|---|
| V1 | اجتياز الفحوصات الحتمية الإلزامية |
| V2 | بلوغ العتبة في **بنود الرُبريك المرتبطة بالمهارة تحديدًا** |
| V3 | مقتطف دليل قابل للفتح ومنسوب إلى تسليم مقفل |
| V4 | اجتياز بوابة التحقق (لا تناقض · لا مبالغة · لا اختلاق · لا توسيع نطاق) |
| V5 | إقرار AI متسق مع إشارات العملية |
| V6 | مصدر موثوق (`platform_controlled` أو `platform_observed`) |
| V7 | الحداثة ضمن `recency_policy` الخاصة بالمهارة |
| V8 | **دليلان مستقلان** للمهارة الأساسية — أو مسار الاستثناء الموثّق |

## 8.4 خط التقييم — الترتيب ملزم
```
Submission → Validation → Deterministic Checks → Integrity Checks → Evaluator
→ Evidence Extraction → Verification → Skill-Level Calculation → Human Review → Publication
```

# 15. القيود والافتراضات والاعتماديات

## 15.1 القيود
- مسار مهني واحد مُفعَّل في P1 · 3 أنشطة فقط · السعودية أولًا · العربية أولًا.
- الثوابت التسعة **غير قابلة للمقايضة** تحت ضغط الجدول.
- **طاقة المراجعة البشرية هي القيد الحقيقي على النمو**، لا البنية التقنية.
- **العبء التحريري:** كل نشاط يحتاج مدخلات خاصة + Integrity Checks + سؤال تبرير + رُبريك بمطابقة مهارات + **اعتماد SME** — والزمن الفعلي **يُقاس ولا يُقدَّر** (D-030).

## 15.2 الافتراضات
| # | الافتراض | حالة التحقق |
|---|---|---|

| A-2 | الرُبريك + النموذج يقارب حكم الخبير بـ≥80% | يُختبر في Phase 0 |

# 16. معايير القبول والتحقق

## 16.1 بوابة خروج Phase 0 *(D-026)*
| المعيار | الهدف |
|---|---|
| إكمال الأنشطة | ≥ 50% ممن بدأ يسلّم خلال 7 أيام |
| جودة التقييم واتفاقه مع المراجع البشري | ≥ 80% على مستوى البند |
| **قيمة `Verified Evidence` لدى مسؤولي التوظيف** | ≥ 60% يعتبرونه مؤشرًا معتبرًا |
| مقاومة مخرَج AI الخام | رسوب ≥ 70% |
| الاستعداد للدفع | ≥ 15% من المُكمِلين |
| تكلفة إنتاج النشاط | **تُقاس فعليًا** — لا تُعتمد التقديرات (D-030) |
| تكلفة AI لكل مستخدم ولكل دليل | تُقاس وتُقارن بالسعر المفترض |

## 16.2 بوابة خروج Phase 1
| المعيار | الهدف |
|---|---|
| التفعيل (تشخيص → أول نشاط خلال 72 ساعة) | ≥ 40% |
| الإكمال (بدء → تسليم خلال 7 أيام) | ≥ 50% |
| القيمة (تسليم → دليل موثّق) | ≥ 80% |
| الإخراج (دليل → تصدير أو مشاركة) | ≥ 60% |
| اتفاق التقييم على 100 تسليم | ≥ 80% مستقر |
| معدل الاعتراض | ≤ 10% |
| ادعاءات بلا دليل | **0%** (بوابة إلزامية) |
| تكلفة الحلقة | < 20% من السعر |
| **النجم الشمالي** | عدد أدلة المهارة الموثّقة المُنشأة أسبوعيًا |

## 16.3 معيار قبول معماري
**اختبار التمديد:** إضافة رُبريك جديد + Activity جديد + قالب إسقاط جديد **بلا تعديل في النواة** · و**اختبار المسار الثاني** (XR-005).

# 18. المصطلحات (Glossary)

| المصطلح | التعريف |
|---|---|
| **Career Graph** | مصدر الحقيقة الوحيد لبيانات المستخدم المهنية |
| **Claim** | ادعاء مهارة حالي لشخص — **مُشتق، يتحرك بين المستويات** |
| **Evidence** | واقعة إثبات واحدة — **ثابتة، لا تُعدَّل ولا تنتهي** |
| **Verified Skill Evidence** | ادعاء مستوفٍ للشروط الثمانية (§8.3) |
| **Evidence Strength** | ظروف إنتاج الدليل: `platform_controlled` … `third_party_asserted` |
| **Activity / ActivitySpec** | نسخة التنفيذ / تعريف النشاط كمحتوى مُصدَّر |
| **Activity Profile** | نوع النشاط: mission · project · simulation · interview · micro_challenge · business_exercise |
| **Integrity Check** | عنصر مُصمَّم في النشاط يقيس الفهم والتحقق والاستقلالية — **ليس أداة اتهام** |
| **Rubric / RubricVersion / ScoringPolicy** | معايير التقييم / إصدارها المجمّد / سياسة التجميع والعتبات |
| **Provenance** | سجل مصدر إلزامي على كل حقيقة |
| **`system_derived`** | حقيقة ناتجة حتميًا من قواعد النظام — **لا تُستخدم لمخرَج LLM** |
| **AgentProposal** | الغلاف الوحيد الذي يدخل به مخرَج وكيل إلى النظام |
| **Journey Engine** | المنسّق الحتمي (A19) |
| **AI Gateway** | بوابة كل استدعاء نموذج: توجيه · قياس · تخزين مؤقت · ميزانية |
| **`human_override_up`** | رفع مستوى بقرار مراجع بشري موثّق — **الصلاحية الوحيدة للرفع** |
| **`design_review_threshold`** | عتبة إحصائية تُنشئ مراجعة تصميم — **وليست سقفًا يرفض حالات صحيحة** |
| **Recency Policy** | سياسة تقادم لكل مهارة أو عائلة مهارات |
| **Validation Activity** | نشاط قصير يرقّي `self_reported` إلى `platform_observed` |
| **Validation Beachhead** | مسار التحقق الأول (Data/BI) — **ليس هوية المنتج** |
| **Proof Layer** | تموضع المنتج: طبقة الإثبات بين التعليم والتوظيف |
