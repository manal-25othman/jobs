# خطة تجربة مسار Junior Frontend كاملًا من البداية إلى النهاية (داخلية، بيانات اصطناعية)

> **الحالة:** خطة للموافقة.
> - **لا مستخدمون حقيقيون، ولا نموذج حقيقي، ولا GitHub حقيقي** في هذه التجربة: GitHub بالمحاكاة، وR2 على كود اصطناعي.
> - المحتوى (الأنشطة، والرُّبريك، والاختبارات، والسيناريوهات، والموارد) **مرشَّح** وموسوم «تجريبي».

| مختبِرون داخليون بدور الخرّيج | 3–5 | يكتبون أعمالًا اصطناعية متعمَّدة: صحيحة، وجزئية، وخاطئة، ومخادعة |
| مراجِع بشري مسمّى | 1–2 | بمنحة `human_reviewer` في بيئة التطوير فقط |

| مالكة المنتج | — | تنشر التجربة بعملية التطوير الموثَّقة، وتقرر بعد كل مرحلة |

## 3. ما يُقاس
- **المقاييس Q1–Q13** على أعمال المختبِرين مقابل حكم المراجِع. هذه أول بيانات حقيقية للمعايرة، وهي اصطناعية بالتصميم.
- زمن المراجعة لكل تسليم، مع اقتراحات A13 ودونها.
- زمن R2 لكل محاولة، وأي اختبار متقلّب.
- ملاحظات الاستخدام: وضوح العربية، والاتجاه من اليمين لليسار، والجوال (390 بكسل)، ولوحة المفاتيح.

## 4. معايير الخروج من التجربة
1. لا خطأ أمني، ولا تسريب للاختبارات أو الحلول أو بيانات مختبِر آخر.
2. Q6 (خطأ غير مصعَّد) = 0.
3. كل اختبار متقلّب مُصلح أو مُستبعد بقرار مكتوب.
4. قائمة مراجعة الخبير للمحتوى مكتملة، **قبل** أي حديث عن مستخدمين حقيقيين.

## 5. ما يلزم قبل البدء (قراراتك)
- الموافقة على هذه الخطة والمشاركين.
- مَن الخبير الذي يراجع الاختبارات والسيناريوهات والأحكام المتوقعة.
- مدة التجربة المقترحة: أسبوعان.
