# سيناريوهات المختبِرين لتجربة Frontend الداخلية (أسبوعان، بيئة التجربة الخاصة)

> **الحالة:** جاهزة.
> - **بيانات اصطناعية فقط.** لا يُرفع عمل حقيقي ولا بيانات شخصية لأحد.
> - **ما يعمل فعليًا وما هو محاكاة:** الجدول في §1، ويظهر الوسم نفسه في الواجهة.

## 1. ما يعمل فعليًا وما هو بالمحاكاة

| الوظيفة | الحالة في بيئة التجربة |
|---|---|
| تسجيل الدخول | **حقيقي**: Supabase Auth، برابط إلى البريد، للمدعوّين فقط |
| اختيار المسار، والتقييم الذاتي، ولقطة المسار، ومصادر التعلّم | **حقيقي** (موارد مرشَّحة موسومة) |
| المدير الافتراضي | **حقيقي في المنصة**، والردود من سيناريو مكتوب مسبقًا (مزوّد الاختبار، **لا نموذج**) |
| تنزيل مواد المشروع والتسليم برفع الملفات | **حقيقي** (تخزين Supabase خاص) |
| GitHub | **محاكاة**: مستودعات اصطناعية، ولا اتصال بـGitHub (تطبيق حقيقي لاحقًا بعد موافقتك) |
| نتائج الاختبارات الآلية | **مسجّلة مسبقًا** لنسخ المستودعات المحاكاة، وموسومة؛ **لا يُشغَّل كود في البيئة**. التسليم بالرفع لا يعرض نتائج آلية |
| التقييم البشري، واقتراحات A13 للمراجِع، والتلميحات، وإعادة التسليم | **حقيقي** في المنصة (A13 ظل، ومزوّد اختبار) |
| واجهات المراجِع والإدارة | **حقيقية** بحسابات الأدوار |
| المستوى والجاهزية والاعتماد المهني | **لا يتغيّر شيء**: العتبات بانتظار الخبير، والنتيجة «لم يُحدَّد بعد» |

## 2. الحسابات (اصطناعية الأدوار، بريد مدعوّ)

| الحساب | الدور | العدد |
|---|---|---|
| مالكة المنتج | `product_owner` + `human_reviewer` | 1 |
| مختبِر خرّيج | بلا دور | 3–5 |
| مراجِع | `human_reviewer` | 1–2 |
| إدارة المسار | `track_admin` | 1 |
| خبير (للعرض فقط) | `sme` | 1 |

## 3. سيناريوهات الخرّيج
كل مختبِر يكتب عملًا اصطناعيًا بشخصية معيّنة.

| # | السيناريو | الشخصية | ما يُلاحظ |
|---|---|---|---|
| G1 | الرحلة كاملة على **الجوال** | مبتدئة متحمسة | الوضوح، والاتجاه من اليمين لليسار، ولا تمرير أفقي |
| G2 | الهدف ← التقييم الذاتي ← اللقطة | مترددة في مستواها | أن التقييم الذاتي لا يرفع مستوى، وأن الخلاصة صادقة |
| G3 | النشاط 1: التصحيح، والتسليم برفع الملفات | من يصلح العَرَض لا السبب | ملاحظة المراجِع، والتلميحات |
| G4 | النشاط 3: ربط GitHub المحاكى ← التسليم من طلب الدمج ← النتائج المسجّلة ← التحسين ← إعادة التسليم من إيداع آخر | صاحبة عمل جيد | المحاولات وإيداعاتها، و«لا تُثبت المهارة» |
| G5 | المدير الافتراضي: أسئلة توضيح، وطلب الحل، والرد على مراجعة الكود | من يحاول أخذ الحل | الرفض بالشخصية، والسقف |
| G6 | محاولة الوصول لعمل مختبِر آخر برابطه | فضولي | الرفض |
| G7 | إلغاء ربط GitHub، ثم محاولة استخدامه | — | توقف القراءة، وبقاء الدليل المثبَّت |

## 4. سيناريوهات المراجِع والإدارة
- **R1:** قائمة المراجعة ← الإسناد ← الطبقة الآلية (الإيداع المثبَّت، والنتائج، واقتراحات A13 المُصعَّدة) ← القرار. **قِس الزمن.**
- **R2:** مراجِع ثانٍ يحاول فتح عنصر مسند لغيره (يُرفض).
- **A1:** واجهات الإدارة الموجودة: الإعدادات والحالات، دون تغيير قيم معتمدة.

## 5. ما يُسجَّل
لكل سيناريو:
- نجح أو لم ينجح؛
- لقطة شاشة عند المشكلة؛
- زمن المراجعة؛
- الملاحظات بالعربية.

يُجمع كل ذلك في جدول مشترك خاص، **لا في المستودع**.
