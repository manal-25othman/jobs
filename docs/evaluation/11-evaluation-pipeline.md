# الوثيقة 6 — Evaluation Pipeline
> خط أنابيب **مُرتَّب وإلزامي الترتيب**. تخطي مرحلة أو تبديل ترتيبها خرق معماري، لا تحسين أداء.

## 1. الترتيب الملزم

```
1 Submission      ← التسليم المقفل
2 Validation      ← صلاحية شكلية        [حتمي · بلا نموذج]
3 Deterministic   ← فحوص المحتوى         [حتمي · بلا نموذج]  ✕ ⟹ توقف
4 Integrity       ← فحوص النزاهة D-013   [حتمي + نموذج محدود]
5 Evaluator       ← الرُبريك بندًا بندًا   [نموذج — أول استدعاء مكلف]
6 Evidence        ← استخراج الدليل
7 Verification    ← بوابة V1..V8
8 Skill Level     ← حساب Claim           [حتمي]
9 Human Review    ← عند التحفيز
10 Publication    ← النشر والإسقاطات
```

> **قاعدة التكلفة الحاكمة:** لا يُستدعى نموذج قبل اجتياز المرحلتين 2 و3. **ما تستطيع قاعدة أن تقرره، لا يجوز لنموذج أن يقرره** — دقة أعلى وتكلفة أقل ورسالة أوضح للمستخدم.

## 2. تفصيل المراحل

### 1) Submission
- **المدخل:** محتوى المستخدم · `AIUsageDisclosure` · ملخص القرارات.
- **المخرج:** `Submission` **مقفل** + `Artifact[]` + تجزئة تحقق.
- **حتمي؟** نعم · **تكلفة:** صفر.
- **يوقف؟** لا.
- **الفشل:** فشل الرفع → المحاولة لا تُنشأ أصلًا (لا تسليم شبح).
- **الأحداث:** `submission.received` · `submission.locked`.

### 2) Validation (الصلاحية الشكلية)
- **يفحص:** اكتمال الحقول الإلزامية · صيغ الملفات · الحجم · وجود إقرار AI · انتماء التسليم لنشاط نشط · عدم تجاوز عدد المحاولات.
- **حتمي؟** نعم · **تكلفة:** صفر · **يوقف؟** **نعم** — رفض شكلي فوري.
- **الفشل:** رسالة تصحيح فورية · **لا يُعد محاولة مستهلكة**.
- **الأحداث:** `validation.passed|failed`.

### 3) Deterministic Checks
- **يفحص:** وجود المخرجات الإلزامية · صحة الأرقام المرجعية · احترام القيود المعلنة · تطابق البنية المطلوبة.
- **حتمي؟** نعم (قابل للتكرار 100%) · **تكلفة:** صفر · **يوقف؟** **نعم عند فشل بند إلزامي**.
- **الفشل:** توقف قبل أي نموذج + **فرصة تصحيح واحدة** + بيان دقيق بما نقص. الادعاء يبقى `Observed`.
- **خطأ في الفحص نفسه:** مسار مراجعة بشرية (لا نعاقب المستخدم على عيب في أداتنا).
- **الأحداث:** `checks.completed` · `checks.blocked`.

### 4) Integrity Checks *(D-013)*
- **يفحص:** التناقضات المدروسة · المعلومات الناقصة · القيم الشاذة · الافتراضات الخفية · **أسئلة الدفاع السياقية**.
- **حتمي؟** **مختلط** — الاكتشاف الصريح حتمي؛ تقييم جودة التبرير يحتاج نموذجًا بسياق ضيق ومكلف بحدود.
- **يوقف؟** لا يوقف الخط، لكن **الفحص الحاسم غير المكتشَف يسقّف الادعاء عند `Practiced`**.
- **الفشل:** انقطاع النموذج → النتيجة `undetermined` وتُعامل معاملة الوضع الآمن (المستوى الأدنى) + مراجعة بشرية متاحة.
- **قيد:** نشاط يمنح `Verified` **يجب** أن يحتوي فحص نزاهة واحدًا على الأقل، وإلا **لا يُعتمد للنشر**.
- **الأحداث:** `integrity.evaluated` · `integrity.flagged`.

### 5) Evaluator (الرُبريك)
- **المدخل:** التسليم · `RubricVersion` · نتائج المراحل 3–4 · `ActivitySpec.skill_mapping`.
- **المخرج:** `EvaluatorResult[]`: درجة + مبرر + **مقتطف داعم** + المهارة + الثقة لكل بند.
- **حتمي؟** لا · **تكلفة:** **الأعلى في الخط** — ولا يُخفَّض النموذج هنا لتوفير التكلفة (جوهر القيمة).
- **قيود:** لا يرى ملف المستخدم ولا أدلته السابقة (منع انحياز) · لا يتجاوز نتيجة حتمية · لا درجة إجمالية بلا بنود.
- **الفشل:** إعادة محاولة واحدة → ثم **طابور مراجعة بشرية**. **لا نتيجة تخمينية إطلاقًا.**
- **الأحداث:** `evaluation.started|completed|failed`.

### 6) Evidence Extraction
- **المدخل:** `EvaluatorResult[]` + مطابقة البنود بالمهارات + قوة المصدر + إقرار AI.
- **المخرج:** `EvidenceProposal[]` — دليل مستقل لكل مهارة بلغت عتبتها.
- **حتمي؟** شبه حتمي (اشتقاق بقواعد؛ الصياغة فقط عبر نموذج).
- **يوقف؟** لا — **"لا دليل" نتيجة مشروعة** تُعرض بوضوح.
- **الفشل:** مهارة خارج التصنيف الداخلي → `unmapped` + مراجعة تحريرية.
- **الأحداث:** `evidence.extracted` · `evidence.none_derived`.

### 7) Verification
- **يفحص:** V1–V8 · التناقض · المبالغة · النطاق · اتساق إقرار AI مع الإشارات.
- **المخرج:** `accept` / `downgrade` / `reject` + **الشرط الساقط محددًا** + إحالة للمراجعة عند اللزوم.
- **قيد مطلق:** **يخفض أو يثبّت، ولا يرفع.** وضعه الآمن عند العطل = الرفض/الخفض.
- **الاستثناء:** منح `Verified` من نشاط واحد يتطلب مراجعة بشرية + `exception_reason` + `reviewer_id` (D-012a).
- **الأحداث:** `verification.completed|downgraded|rejected|exception_granted`.

### 8) Skill-Level Calculation
- **المدخل:** كل أدلة المهارة + التحقق + الحداثة + عدد الأدلة المستقلة.
- **المخرج:** `Claim.level` + `level_reason` + `recency_status` + `confidence`.
- **حتمي؟** **نعم بالكامل** — قواعد صريحة، بلا نموذج.
- **قيد:** `Activity Score ≠ Skill Verification Level` (الثابت التاسع).
- **الأحداث:** `claim.recomputed` · `claim.level_changed`.

### 9) Human Review
- **متى:** التفصيل في الوثيقة 7 (إلزامي / اختياري).
- **المخرج:** قرار موثّق: تثبيت · خفض · **رفع (صلاحية بشرية حصرية)** · طلب معلومات.
- **حتمي؟** لا · **تكلفة:** بشرية لا نموذجية — وهي **قيد الطاقة الأساسي على النمو**.
- **الأحداث:** `human_review.requested|assigned|completed`.

### 10) Publication
- **يشمل:** تحديث `Claim` · إنشاء `Achievement` · توليد الإسقاطات (CV/LinkedIn/Case Study) · فحص الخصوصية قبل النشر · تحديث Project Hub.
- **قيد:** النشر العام **بموافقة صريحة فقط** · لغة العرض لا تتجاوز المستوى.
- **الأحداث:** `achievement.unlocked` · `asset.generated` · `case_study.published`.

## 3. ضمانات الخط

| الضمان | القاعدة |
|---|---|
| **الترتيب** | لا تُنفَّذ مرحلة قبل نجاح ما قبلها؛ لا استدعاء نموذج قبل المرحلتين 2–3 |
| **التكرارية (Idempotency)** | إعادة تشغيل مرحلة على تسليم مقفل تُنتج سجلًا جديدًا ولا تستبدل القديم |
| **إمكانية الإعادة (Replay)** | كل مرحلة تشير إلى إصدار محدد (Spec · Rubric · Prompt · Model) فيمكن إعادة التشغيل للمعايرة |
| **الشفافية** | كل درجة تقابلها: بند + مبرر + مقتطف؛ لا رقم بلا سند |
| **الوضع الآمن** | كل عطل أو التباس ⇒ المستوى الأدنى + شرح (D-015) |
| **التكلفة** | سقف لكل مرحلة؛ تجاوزه يوقف المرحلة غير الحرجة لا الخط الحرج |

**الخط الحرج الذي لا يُخفَّض أبدًا:** المراحل 1 → 8. ما يُخفَّض عند ضغط الميزانية: Companion · تدخلات المدير · صياغة الإسقاطات (تعود لقوالب حتمية).

---

## 4. مسار الاعتراض
اعتراض المستخدم **لا يعدّل** التقييم الأصلي — بل يُنشئ `Evaluation` مراجعة جديدة مرتبطة به، ويُسجَّل القراران معًا. القرار النهائي مُعلَّل، ويُحتسب في **مقياس اتفاق التقييم** (بوابة خروج P1).
