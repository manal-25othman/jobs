# الوثيقة 8 — Human Review Architecture
> المراجعة البشرية **آلية معايرة وضمان مصداقية**، لا خدمة عملاء. وهي **قيد الطاقة الأساسي على النمو** — تُصمَّم لتنكمش بالوقت، لا لتتوسع.

## 1. متى تكون إلزامية

| # | المحفّز | السبب |
|---|---|---|
| H-1 | **كل التسليمات حتى 100** (نافذة المعايرة) | قياس الاتفاق — بوابة خروج P1 |
| H-2 | **كل ترقية إلى `Verified`** خلال نافذة المعايرة | أثمن ادعاء، والأعلى خطرًا |
| H-3 | **مسار الاستثناء D-012a** (دليل واحد) | شرط منصوص عليه في القرار — بلا استثناء |
| H-4 | **اعتراض المستخدم** | حق إجرائي |
| H-5 | **تعارض المقيّم مع بوابة التحقق** | لا يُحسم آليًا |
| H-6 | **نزاهة N4** (تكرار عبر أنشطة) | لا أثر دائم على حساب بقرار آلي |
| H-7 | **فشل المقيّم بعد إعادة محاولة** | بديل الطابور، لا التخمين |
| H-8 | **أول 20 تسليمًا لكل `RubricVersion` أو `ActivitySpec` جديد** | لا محتوى جديد بلا معايرة |
| H-9 | **`confidence = low` مع طلب المستخدم** | إنصاف |
| H-10 | **مهارة `unmapped`** | قرار تحريري لا تقييمي |

## 2. متى تكون اختيارية
عيّنة عشوائية دورية بعد نافذة المعايرة (5–10%) · فحوص موضعية عند تغيّر نموذج أو إصدار prompt · طلب المستخدم حين تكون الطاقة متاحة (يُعلن التوفر بصدق، ولا يُوعَد بما لا يُنفَّذ).

## 3. صلاحيات المراجع

| الصلاحية | مسموح؟ | القيد |
|---|---|---|
| تثبيت القرار الآلي | نعم | — |
| خفض المستوى | نعم | مبرر إلزامي |
| **رفع المستوى** | **نعم — وهو الطرف الوحيد الذي يملكها** | `human_override_up` بحقوله الإلزامية الثمانية (§3-أ) + مراقبة المعدل |
| طلب معلومات إضافية | نعم | يُوقف المؤقت ولا يُغلق الحالة |
| تعديل محتوى التسليم | **لا** | التسليم مقفل |
| تعديل الرُبريك | **لا** | قناة تحريرية منفصلة |
| تجاوز فحص حتمي | **لا** | يُصعَّد كعيب في الأداة |

### 3-أ. سجل `human_override_up` *(D-021 — كل الحقول إلزامية)*
`reviewer_id` · `reason` (نص مكتوب، لا اختيار من قائمة) · `linked_evidence[]` · `rubric_version` · `previous_level` · `new_level` · `timestamp` · `audit_event`.

**حدود الصلاحية — لا يجوز للمراجع تجاوز شرط جوهري مفقود:**

| الحالة | مسموح بالرفع؟ |
|---|---|
| لا يوجد `Evidence` أصلًا | **لا** |
| لا يوجد `Activity`/`Submission` صالح | **لا** |
| لا يوجد `rubric_version` مرجعي | **لا** |
| فشل فحص حتمي إلزامي | **لا** — يُصعَّد كعيب في الأداة |
| يوجد دليل وتسليم ورُبريك، والخلاف على **الحكم** | **نعم** |

> **الغاية: تصحيح حكم النظام، لا إنشاء إثبات من العدم.** المراجع يصحّح قراءة الدليل؛ ولا يخلق دليلًا.

> **ملاحظة تصميم:** `A18` لا يرفع أبدًا، والمراجع البشري يرفع. هذا يجعل **الرفع دائمًا فعلًا بشريًا موثّقًا** — وهو ما نستطيع الدفاع عنه أمام مسؤول توظيف.

## 4. سجل قرار المراجعة
`review_id` · `reviewer_id` · دور المراجع ومؤهله · `submission_ref` · `evaluation_ref` · القرار · **البند/الشرط محل القرار** · المبرر المكتوب · الوقت المستغرق · هل خالف القرار الآلي؟ · درجة الاتفاق البندي · تعارض مصالح؟ · الإصدارات (rubric · policy · model · prompt) · الطابع الزمني.
**غير قابل للتعديل** · يُنشر كحدث · يُغذّي مقياس الاتفاق ومعايرة المراجعين.

## 5. ضوابط الجودة والإنصاف
- **مراجعة عمياء:** المراجع لا يرى هوية المستخدم ولا صورته ولا جامعته — يرى العمل والرُبريك فقط.
- **قياس الاتفاق بين المراجعين:** عيّنة مزدوجة دورية؛ اختلاف المراجعين عن بعضهم مشكلة **رُبريك** قبل أن يكون مشكلة أشخاص.
- **تدوير:** لا يراجع الشخص نفسه نفس المستخدم مرتين متتاليتين.
- **تعارض المصالح:** إفصاح إلزامي وإعادة إسناد.
- **حد زمني معلن** للاعتراضات، ويُبلَّغ المستخدم بحالته.

## 6. نموذج الطاقة (قيد النمو الحقيقي)
- تُقاس: مراجعات/ساعة · كلفة المراجعة · طول الطابور · زمن الاستجابة.
- **قاعدة حماية:** تجاوز الطابور حدًا متفقًا عليه ⇒ **إبطاء الاستحواذ أو تضييق نافذة المعايرة** — **لا** تخفيف معايير `Verified`.
- **خطة الانكماش:** نافذة معايرة (100 تسليم) → عيّنة 20% → عيّنة 5–10% + المحفّزات الإلزامية فقط. الشرط في كل مرحلة: اتفاق ≥ 80% مستقر.
- **ما لا ينكمش أبدًا:** H-3 (الاستثناء) · H-4 (الاعتراض) · H-6 (النزاهة N4).
