# نَقْلة / NAQLA — Domain Model
**الإصدار:** 0.1.0 · **التاريخ:** 2026-09-26 · **الحالة:** مسوّدة للمراجعة الداخلية — Phase 0

> **مصدر الحقيقة للقواعد هو `packages/domain`.** هذه الوثيقة تشرحه ولا تحل محلّه.
> عند أي اختلاف بين الوثيقة والكود، **الكود هو الصحيح** والوثيقة تُصحَّح.

---

## ٠. المبادئ الحاكمة لهذا النموذج

1. **لا حقل لأن الواجهة تحتاجه.** كل حقل يعود إلى متطلب أو ثابت أو ضرورة تشغيلية، ومذكور بجانبه.
2. **الثوابت في القاعدة لا في التطبيق.** ما يمكن فرضه بقيد `CHECK` أو مفتاح أجنبي يُفرض هناك؛ فالقاعدة لا تنسى.
3. **التاريخ لا يُعاد كتابته.** الجداول التي تحمل تاريخًا تُضاف إليها الصفوف ولا تُعدَّل.
4. **الغياب ليس حالة مخزَّنة.** `gap` مثلًا رتبة عرض، لا صف في جدول.
5. **الخصوصية تصنيف على الكيان، لا إعداد يُنسى.** كل كيان يحمل `privacy classification`.

### تصنيف الخصوصية المستخدم في الجداول أدناه

| التصنيف | المعنى |
|---|---|
| `private_never_shareable` | لا يغادر الحساب بأي مسار، مهما كانت الإعدادات |
| `private_shareable_derived` | خاص، ويجوز مشاركة **مشتق معتمد** منه فقط |
| `private_publishable` | خاص افتراضيًا، ويجوز نشره كما هو **بعد اعتماد صريح** |
| `non_personal` | محتوى منصة بلا بيانات شخصية |

### ملاحظة على السلّم: مفرداتان محفوظتان

سجلات المنتج (`docs/model/10`) تسمّي السلّم:
`Observed → Practiced → Demonstrated → Verified` (+ `Aging` · `Historical`).
التصميم المُجمَّد (§8) يسمّيه:
`Gap → Self-reported → Practiced → Demonstrated → Verified`.

**كلاهما محفوظ ولم يُدمج.** التصميم يشقّ `Observed` إلى حالتين مرئيتين للمستخدم:
`gap` (الدور يطلبها ولم يفعل شيئًا) و`self_reported` (أعلنها بلا مشروع).
داخليًا كلتاهما `Observed`: لا تُعرض علنًا (D-017)، ولا تبلغ `demonstrated` بلا تسليم مُقيَّم.
**والفرق بينهما ليس تجميليًا**: مهارة `self_reported` موجودة في سيرة المستخدم **تُوسَم كادعاء غير مدعوم**، بينما `gap` لا شيء يُوسَم.
هذا الفرق كشفه اختبار وحدة سقط عند محاولة دمجهما، وهو مثبَّت الآن في `presentationFor()`.

## ٩ب. `Evidence Item` — عنصر الدليل (سجل المادة) *(Phase 1 — Configurable Track Architecture)*

> **ليس `Evidence`.** `Evidence` واقعة مُثبتة يكتبها التقييم وحده وتحرّك الادعاء (INV-1). `Evidence Item` **مادة** قدّمها المستخدم أو سجّلها النظام: رابط مستودع · ملف · شرح نصي · تسليم مقفل · نتيجة فحص آلي · إفصاح · محاولة سابقة. **لا يحرّك ادعاءً أبدًا**، ولا يُحتسب في عدّ الأدلة قبل التقييم.

| | |
|---|---|
| **الغرض** | سجل مُنمَّط لكل ما يمكن أن يُقيَّم أو يُراجَع، بنوعه ومصدره ومحاولته، مرتبطًا بعدة مهارات. |
| **المُعرِّف** | `evidence_item.id` |
| **الملكية** | المستخدم — يقرأ ويضيف مادّته (`user_direct`)؛ عناصر التسليم (`user_submission`) وعناصر النظام (`system`) تُكتب عبر service role داخل معاملة التسليم/التقييم نفسها |
| **دورة الحياة** | `draft → submitted → withdrawn \| superseded` — أمامية فقط؛ **لا تعديل بعد التقديم** (مُحفِّز يرفض)، ولا حذف (سحب فقط) |
| **النوع** | صف في سجل `evidence_item_type` (**بيانات لا enum**): `channel ∈ url/file/text/activity/system` · `required_fields` · `match_rule` للتصنيف · `review_status` — **كل الأنواع المبذورة `draft` = DRAFT / NOT VALIDATED** |
| **المهارات** | `evidence_item_skill` — عدة مهارات لعنصر واحد؛ `linked_by ∈ user/system`؛ `weight` **دائمًا NULL** (لا وزن قبل رأي الخبراء) |
| **الجسر إلى الواقعة** | `evidence_derivation` — `recorded_as` (عنصر نتيجة الفحص الآلي للتشغيلة) · `evaluated_from` (المادة التي قُرئت)؛ تُكتب مع التقييم فقط |
| **المحاولات** | `attempt_number` لكل مشروع (عدّ لا إذن)؛ المحاولة الجديدة تجعل السابقة `superseded` وتُسجَّل `previous_attempt` |
| **الثابت المُسمّى** | `claimEffectOfEvidenceItem() === 'none'` — يُعاد مع كل عنصر في الـAPI حتى لا تخلط واجهة المادة بالإثبات |

**لماذا سجل منفصل لا أعمدة على `evidence`:** كل قارئ لـ`evidence` اليوم (عدّ الأدلة في `me/skills` · حقائق الوكلاء · التقرير · سحب D-077) يعامل الصف «مُثبتًا بتقييم». كتابة مادة المستخدم فيه كانت ستغيّر العدّ وحقائق الوكلاء قبل أي تقييم — تغيير سلوك إنتاجي لا تسمح به المرحلة.

## ١١. `Evidence State` — حالة الدليل

| | |
|---|---|
| **الغرض** | موقع المهارة على السلّم، كما يراه المستخدم. |

**`gap` ليست صفًّا.** قيد `claim_gap_is_not_stored` يرفض تخزينها: الفجوة هي **غياب** ادعاء، وتُحسب بالفرق بين متطلبات الدور والادعاءات الموجودة. تخزينها كان سيعني صفوفًا لكل مهارة لم يلمسها المستخدم قط، ثم سؤالًا لا إجابة له: متى تُنشأ؟

**المقارنة بالرتبة لا بالنص.** الواجهة لا تستنتج الاتجاه من ترتيب الحروف (§8)، والقاعدة تفرض ذلك بـ`evidence_ordinal(to) > evidence_ordinal(from)`.

## ١١ب. `Skill Progress` — رحلة المهارة *(Phase 2 — Configurable Track Architecture)*

> **بُعد ثانٍ منفصل عن حالة الدليل.** `Evidence State` (§١١) = **مستوى التحقق**: ما أثبته التقييم. `Skill Progress` = **موقع المستخدم في الرحلة** على المهارة: لم تبدأ · قيد العمل · مُسلَّمة · قيد المراجعة البشرية · تحتاج دليلًا إضافيًا · سُجِّل دليل مُقيَّم. **لا يُشتق أحدهما من الآخر، ولا يحرّك أحدهما الآخر.** إكمال نشاط يحرّك الرحلة ولا يرفع مستوى التحقق أبدًا.

| | |
|---|---|
| **الغرض** | إجابة «أين أنا في هذه المهارة وما الخطوة التالية؟» دون أن تُقرأ إثباتًا. |
| **المُعرِّف** | `skill_progress.id` — صف واحد لكل (مستخدم، مهارة) |
| **الملكية** | المستخدم يقرأ؛ **المحرّك وحده يكتب** (service role) داخل معاملة الحدث المُنتِج |
| **الحالات** | صفوف `skill_progress_state` (**بيانات لا enum**)؛ قيد يرفض أي رمز من سلّم الدليل (`gap/self_reported/practiced/demonstrated/verified`)؛ حالة ابتدائية واحدة مفعَّلة |
| **المحفّزات** | صفوف `skill_progress_trigger` — `project.created` · `evidence_item.added` · `submission.created` · `evaluation.queued_for_human` · `evaluation.completed` · `evidence.withdrawn`؛ و`more_evidence.requested` مسجَّل **بلا مُنتِج** (`active = false`) |
| **قواعد الانتقال** | صفوف `skill_progress_transition` (`from` · `to` · `trigger` · `guard` تصريحي `{"produced_evidence": true}` / `{"x": {"not": …}}` / `{"x": {"in": […]}}` · `version` · `review_status`) — **١٤ قاعدة مبذورة كلها `draft` = DRAFT / NOT VALIDATED**؛ `approved` يشترط `approved_by/at` |
| **القرار** | `nextProgress(rules, current, trigger, facts)` نقي في النطاق: قاعدة مفعَّلة واحدة تطابق؛ **قاعدتان = خطأ بيانات يُرمى**؛ لا قاعدة = «لا انتقال» صريح يُسجَّل |
| **السجل** | `skill_progress_event` **إضافة فقط**: كل إصدار محفّز يُسجَّل، طُبِّق أم لا (`transitioned` · `no_matching_rule` · `rules_inactive` · `backfilled`) مع رقم إصدار القاعدة والوقائع ومرجع الحدث |
| **الإنتاج** | قواعد `draft` **لا تُطبَّق** في الإنتاج؛ المحرّك يسجّل `rules_inactive` ويُعلن السبب في الـAPI (`engine.active=false`) بدل الصمت |
| **الثابت المُسمّى** | `verificationEffectOfProgress() === 'none'` — يُعاد مع كل صف |

**الحالات الخمس** (`evaluation_outcome`):

| الحالة | المعنى | المصدر |
|---|---|---|
| `passed` | بلغ العتبة؛ يجوز اشتقاق دليل | doc 11 §5–§6 |
| `below_threshold` | عمل حقيقي مُقيَّم دون العتبة. **«لا دليل» نتيجة مشروعة** وتُعرض بوضوح | doc 11 §6 |
| `blocked_by_checks` | فشل فحص حتمي إلزامي؛ يتوقف الخط وتُتاح فرصة تصحيح واحدة | doc 11 §3 |
| `undetermined` | انقطاع نموذج النزاهة. الوضع الآمن: المستوى الأدنى + مراجعة بشرية. **ولا درجة مُخمَّنة أبدًا** | doc 11 §4 |
| `needs_human_review` | فشل المُقيِّم بعد إعادة محاولة واحدة، أو تصعيد | doc 11 §5 · §9 |

> ✅ **`OPEN-EVAL-01` مُغلق بقرار المالكة (D-051): المفهومان يبقيان منفصلين.**
>
> `EvaluationOutcome` يجيب: **ماذا حدث أثناء محاولة التقييم؟**
> `VerificationOutcome` يجيب: **ماذا قرّرت خطوة تحقق مستقلة أو بشرية؟**
>
> **ولا يُدمجان** في تعداد واحد ولا عمود حالة واحد: تقييم جرى بلا خلل قد ترفضه المراجعة، ومراجعة قد تُصعَّد بينما التقييم `passed`. دمجهما يجعل «انتهت الآلة» و«وافق إنسان» شيئًا واحدًا — وهو الفرق الذي يقوم عليه سلّم `Verified` كله.
>
> **العلاقة والتعدّدية:**
> ```
> Submission ─1:N→ Evaluation ─1:N→ EvaluationResult ─0:1→ Verification
>             (محاولات)          (تاريخ لا يُعدَّل)      (قرار عن نتيجة)
> ```
> · **1:N للمحاولة** — يجوز إعادة تقييم تسليم (اعتراض، إعادة محاولة).
> · **1:N للنتيجة** — إعادة التقييم **تُضيف** صفًّا مرتبطًا بـ`supersedes_result_id`.
> · **0:1 للتحقق** — ليست كل نتيجة تُتحقَّق، **وقرار واحد لكل نتيجة**: قراران على نتيجة واحدة التباس بلا قراءة صحيحة.
>
> **دورتا الحياة** منفصلتان تمامًا في `packages/domain/src/verification.ts`:
> `Evaluation`: `queued → running → completed | failed → queued_for_human · completed → disputed → revised`
> `Verification`: `pending → evaluating → accepted | downgraded | rejected | escalated_to_human → human_resolved | exception_granted`
>
> **وقاعدة مطلقة على التحقق:** يخفض أو يثبّت، **ولا يرفع أبدًا** — مفروضة بقيد `verification_never_raises`. و`downgraded` **تثبّت عند الحالة الحالية** ولا تُنزل المستخدم، لأن v1 لا يُنمذج التراجع أصلًا.

| الحقل | لماذا | قابل للتعديل؟ |
|---|---|---|
| `rubric_version_id` | **INV-2** — قيد `evaluation_result_scored_needs_rubric` | ⛔ |
| `activity_spec_id` + `activity_spec_version` | **INV-7** — نفس القيد | ⛔ |
| `supersedes_result_id` | فهرس فريد: **نتيجة واحدة لا تُستبدَل مرتين** | ⛔ |
| `human_reviewer_id` + `role_performed` | `FR-P-037` · D-038 — **من** راجع، و**بأي صفة**، منفصلان لأن الـSME والمراجع قد يكونان شخصًا واحدًا في Phase 0 | ⛔ |

## ١٣ب. `Assessment` و`Verification Decision` — ما لوحظ وما تقرّر *(Phase 3 — Configurable Track Architecture)*

> ثلاثة سجلات كانت واحدًا: **`Evaluation Result`** (§١٣؛ الدرجة والتاريخ — كما هو) · **`Assessment`** = ما **لاحظه** المُقيِّم · **`Verification Decision`** = ما **قرّرته السياسة** (أو إنسان مُسمّى) بشأن ذلك. لا يُدمج الاثنان: تقييم كامل قد يُرفض تحققه، وقرار قد يُصعَّد بينما التقييم «ناجح».

| | |
|---|---|
| **`Assessment`** | لكل نتيجة تقييم ولكل مُقيِّم (`rule` · `human` · `llm` محجوز): من قيّم ومرجعه · إصدارات الرُبريك والنشاط ومجموعة القواعد وسياسة السياق · المدخلات المستعملة (مفاتيح الأدوات · عناصر المادة · **الهوية مستبعدة**) · النتيجة الخام كاملة · الثقة (= أضعف بند، تجميع وقائع لا عتبة). لكل بند: الحالة (`met` · `partially_met` · `not_met` · `pending_human` · `not_applicable`) · الدليل المستخدم · **الدليل الناقص** · الملاحظات · القوة · الفجوات · الثقة · نوع المُقيِّم · **الإجراء التالي** (من المفاتيح الناقصة لا من اختراع). **ثابت** (لا تعديل ولا حذف). |
| **`Verification Policy`** | **صف بيانات** (`key` · `version` · `review_status`): النتائج التي ينطبق عليها · قبول اقتراح الرُبريك · سقف اختياري · **حدّ ثقة** · **حدّ أدلة مستقلة** · قواعد تصعيد · قاعدة الحجب · اشتقاق لكل مهارة (H6) · من يقرّر. **المبذورة `default@1` مسودة تساوي سلوك ما قبل المرحلة حرفيًا** (اختبار شامل يثبت التطابق)؛ كل مقبض خبراء `null`/معطَّل. قيد في القاعدة: **لا يمكن حتى تسمية `llm`/`agent` فاعلَ قرار**. |
| **`Verification Decision`** | لكل تقييم **ولكل مهارة** قرار مُسجَّل حتى حين لا ينطبق (`not_applicable`): السياسة ومفتاحها وإصدارها **وحالتها وقت القرار** · إصدار مجموعة القواعد · من قرّر (`policy` أو `human` مُسمّى — **`llm` ممنوع بنيويًا**) · الحالة السابقة والمقترحة والناتجة · الثقة · السبب · رابط `verification` القديم و`evidence` الناتج · `human_override_of` (التجاوز البشري صف **جديد** يشير إلى ما يتجاوزه، ولا يمحوه). قيود: لا رفع فوق المقترح، لا تنزيل تحت السابق، ثابت. |
| **الثوابت في الكود** | `decideWithPolicy` نقي: `llm` لا يقرّر (INV-3) · التحقق يخفض أو يثبّت (INV-9 عبر `decideVerification` القائم) · سقف الإنتاج `demonstrated` (D-059/D-102) · سبب مكتوب إلزامي. |
| **ما لا يفعله** | لا يغيّر أهلية CV/LinkedIn (`career_presentation_rule`/`presentationFor` كما هما — Phase 7) · لا يمسّ `evaluation_result` ولا `verification` ولا `evidence_transition`. |

## ١٣ج. `Track Configuration` وطبقة السياسات — الإعداد كبيانات مُصدَّرة *(Phase 4 — Configurable Track Architecture)*

> كل صف إعداد محكوم يحمل بُعدين مستقلين: **`review_status`** (المصادقة الخبيرة) و**`activation`** (هل يستعمله المنتج): `inactive` (الافتراضي لكل صف جديد؛ لا يُستشار) · `development_only` (خارج الإنتاج فقط) · **`legacy_baseline`** (السلوك الذي كان قائمًا قبل الطبقة؛ يعمل في الإنتاج **لهذا السبب وحده لا لأنه مُصادَق عليه**؛ لا يُنشئه إلا migration — `baseline_of` مجمَّد عند الإدراج) · `production_active` (ترقية صريحة مُدقَّقة لصف **مُصادَق عليه**). صف نشط واحد لكل مفتاح؛ صف جديد لا يحلّ محل نشط بالصدفة.

| | |
|---|---|
| **`Track Configuration Version`** | الإعداد المُجمَّع لمسار: أي إصدار من سياسة التحقق وسياسة السياق وسياسة الادعاء وسياسة التحدي، وإصدار قواعد الرحلة، **ولقطة** حقول TrackSkill وقت الإنشاء. `v1 legacy_baseline` للمسارات التي سبقت الهجرة؛ المسار المستورد لاحقًا يأخذ `v1 draft` (`development_only` خارج الإنتاج، `inactive` فيه). **المحتوى ثابت منذ أول تفعيل؛ التغيير إصدار جديد.** لا قاعدة جاهزية بعد (قيد يمنع ربطها حتى Phase 5). |
| **`Assessment Context Policy`** | لكل نوع مدخل: `required` · `optional` · `excluded` (أدوات التسليم · المادة · الإفصاح · المحاولات السابقة · قرارات المراجعين · **الهوية والملف الشخصي مستبعدان بقيد قاعدة وبالكود معًا**). `default@1 legacy_baseline` = ما كان المُقيِّم يراه قبل الطبقة. كل `assessment` جديد يسجّل `context_policy_version` و`context_policy_id`. |
| **`Claim Policy`** | لكل نوع ادعاء (CV bullet · وصف مشروع · LinkedIn skill/project/headline/about · summary · case study · profile · report): المستوى الأدنى · عدد الأدلة · قوة المصدر · هل يلزم قرار تحقق · **`requires_user_approval = true` بقيد لا يُعطَّل** (BR-021). **مُستهلَكة منذ Phase 7** (§١٧ب): `legacy_presentation@1` أساس توافق يعيد `presentationFor()` حرفيًا؛ صفوف `default@1` مسودة غير مفعَّلة. |
| **`Challenge Policy` + `Verification Challenge Type`** | سجل أنواع التحدي (سؤال استيضاح · شرح · تعديل لاحق · قراءة كود · عرض حي) **معطَّل غير مُصادَق**؛ سياسة `default@1` `draft` `inactive` بقاعدة تشغيل `{}` = لا تحدٍّ. **لا مُشغِّل تحدٍّ في المنتج** (`CHALLENGE_RUNNER_EXISTS = false`). |
| **TrackSkill** (`role_requirement`) | حقول عرض/إعداد: `category` · `display_order` · `expected_level` · `readiness_contribution` (`null` = غير محسوم؛ لا عتبة) · `enabled` · **`classification_status`** (`pending_expert_validation` افتراضيًا؛ `approved` يشترط مراجعًا). **`is_core` لا يُعرض «أساسية» قبل الاعتماد** (`trackSkillBadge`). |
| **`Config Change`** | سجل إضافة فقط لكل تغيير تفعيل/حالة مصادقة، بفاعل وسبب إلزاميين؛ القاعدة ترفض التغيير بلا `naqla.config_actor`/`naqla.config_reason`. الأفعال: `config-approve` · `config-activate` · `config-new-version` (CLI؛ واجهة الإدارة Phase 8). |
| **الثوابت في الكود** | `resolveActiveConfig`: الإنتاج يستشير `production_active` ثم `legacy_baseline` **ولا يستشير مسودة أبدًا**؛ `production_active` غير المُصادَق عليه ⇒ خطأ ثابت لا استعمال · `assertActivationAllowed` · الهوية مستبعدة · موافقة المستخدم على الادعاء لا تُعطَّل · لا قاعدة جاهزية (`READINESS_RULES_EXIST = false`). |
| **التاريخ** | `assessment` و`verification_decision` يسجّلان `track_config_version_id` و`context_policy_id` و`config_resolution`؛ الصفوف السابقة `null` = ما قبل 0014 وتبقى كما هي (ثابتة). **لا تعديل إعداد يُعيد حساب نتيجة تاريخية.** |

## ١٣د. `Readiness` — الجاهزية كتقرير على قواعد مُعدَّة *(Phase 5 — Configurable Track Architecture)*

> **أنواع القواعد كود، وقيمها بيانات مُصدَّرة.** لا عتبة في الكود: لا «٣ من ٧» ولا «٧٠٪» ولا «كل الأساسية». **لا مجموعة قواعد مبذورة** ولا يمكن وجود «أساس توافق» للجاهزية (قيد) لأن لا سلوك جاهزية سبق هذه المرحلة.

| | |
|---|---|
| **أنواع القواعد (كود)** | `required_skill_at_level` · `non_compensable_skill` · `min_skills_at_level` (`scope ∈ all/enabled/core`) · `all_core_skills_at_level` · `all_skills_at_expected_level` · `min_evidence_per_skill`. كل نوع يقول أي وقائع يقرأ وكيف يُستوفى؛ **القيم** (المهارة · المستوى · العدد) صفوف `readiness_rule` داخل `readiness_rule_set` مُصدَّرة ومحكومة بنموذج التفعيل. |
| **الحالات** | لا مجموعة فعّالة ⇒ **`not_yet_configured`** بالعنوان المحايد «معيار الجاهزية لهذا المسار قيد الاعتماد» · مجموعة مفعَّلة غير مُصادَق عليها (تطوير فقط) ⇒ **`pending_validation`** (وقائع القواعد تُعرض مسودةً، **بلا نتيجة إجمالية**) · مجموعة مُصادَق عليها مُفعَّلة للإنتاج ⇒ **`evaluated`** (`meets_rule_set` / `does_not_meet_rule_set`؛ **لا نسبة ولا مستوى**). |
| **`indeterminate`** | قاعدة تعتمد على تصنيف غير مُصادَق عليه (مثل «كل الأساسية» بينما `is_core` قيد الاعتماد) أو مستوى متوقع غير محسوم ⇒ **غير محدَّدة**، لا تُستوفى ولا تُخفَق بصمت. |
| **الثوابت** | الجاهزية **لا تكتب** ادعاءً ولا دليلًا ولا رحلة (`verificationEffect: 'none'`) · مستوى التحقق **لا يعني** جاهزية · قاعدة مفعَّلة قيمها ثابتة (التغيير إصدار جديد) · لا baseline للجاهزية. |
| **السجل** | `readiness_evaluation` إضافة فقط: كل لقطة تذكر مجموعة القواعد ومفتاحها وإصدارها وحالتها وكيف حُلّت، وإصدار إعداد المسار، وإصدار مجموعة قواعد النطاق. تغيير القواعد لاحقًا لا يمسّها. |
| **مساهمة المهارة** | ما تقوله الإعدادات فقط: القواعد التي تسمّيها (بنتيجتها وإن كانت غير قابلة للتعويض) · المستوى المتوقع وحالة اعتماده · `readiness_contribution` (`counts`/`informational`/غير محسوم) · الشارة (`pending_expert_validation` حتى الاعتماد). |
| **صفحات المهارة** | `/skills` و`/skills/[id]`: **أربعة أبعاد منفصلة** — الرحلة · مستوى التحقق · الأدلة (مادة مُقدَّمة ≠ دليل مُقيَّم) · المساهمة في الجاهزية — بالنظام المُجمَّد؛ لا «أساسية/مساندة» قبل الاعتماد؛ لا نسبة. |
| **أثر رأي الخبراء** | «JavaScript إلزامية» = `required_skill_at_level` · «Debugging أساسية» = `is_core` + اعتماد `classification_status` · «٥ مهارات على الأقل» = `min_skills_at_level {min_count: 5}` · «غير قابلة للتعويض» = `non_compensable_skill` · «مستويات متوقعة مختلفة» = `expected_level` + `all_skills_at_expected_level` — **كلها إصدار مجموعة قواعد/إعداد جديد بلا كود**. |

## ١٤. `Evaluation Criterion` — بند التقييم

| | |
|---|---|
| **الغرض** | درجة بند واحد داخل نتيجة، مع مبرره ومقتطفه. |
| **المُعرِّف** | `evaluation_criterion_score.id` · فريد على (`result`, `criterion_key`) |
| **دورة الحياة** | إضافة فقط، مع النتيجة |

**قيدان يحرسان جودة التقييم:**
- `rationale` **غير فارغ إلزاميًا** — درجة بلا مبرر مكتوب ليست نتيجة (doc 11 §5).
- `criterion_score_in_range` — `0 <= score <= max_score`.

`supporting_excerpt` يجعل الدرجة **قابلة للمراجعة**: مراجع بشري يرى على أي سطر بُنيت.

| | |
|---|---|
| **الغرض** | فحص سلامة على التسليم (D-013، وسُمّي «Integrity Check» بدل «trap»). |
| **المُعرِّف** | `integrity_check.id` |
| **الخصوصية** | `private_never_shareable` |

**`classification` حقل حاكم:** `user_facing` يجوز شرحه للمستخدم، و`assessment_only` **لا يُعرض ولا يُشارك بأي مسار** — لأن عرض الفحص يعلّم كيف يُجتاز. وRLS لا تمنح أي سياسة قراءة لهذا الجدول لأي عميل، **وهذا مُختبَر**.

## ١٦. `AI Disclosure` — إقرار استخدام الذكاء الاصطناعي

| | |
|---|---|
| **الغرض** | ما يقوله المستخدم عن استعانته بالذكاء الاصطناعي في تسليم بعينه. |
| **المُعرِّف** | `ai_disclosure.id` · **واحد لكل تسليم** |
| **دورة الحياة** | يُسجَّل مع التسليم، ولا يُعدَّل بعده |
| **الخصوصية** | `private_never_shareable` |

**أهم ما في هذا الجدول ليس فيه: لا عمود عقوبة.**
سياسة الاستخدام تقول إن الإفصاح **لا يخفض الدرجة بذاته**، وحقل غير موجود لا يُساء استخدامه لاحقًا. الأوضاع الثلاثة مُعدَّدة، وقيد `ai_disclosure_prohibited_means_none` يرفض إقرار تأليف على نشاط `ai_prohibited`.

إشارات التثليث (I1–I6) وسلّم N0–N4 **مُنفَّذة في `packages/domain/src/ai-disclosure.ts`**، ونوع الإرجاع نفسه يمنع العقوبة: `scorePenaltyApplied: false` قيمة حرفية لا متغيّر.

## ١٦ب. الإفصاح المُهيكل وطبقة النزاهة *(Phase 6 — Configurable Track Architecture)*

> **استخدام الذكاء الاصطناعي ليس غشًا.** الغرض: هل يفهم المستخدم العمل الذي قدّمه، ويتحقق منه، ويعدّله، ويستطيع التفكير فيه — **سواء استخدم AI أم لا**. الإفصاح **سياق** للتقييم: ليس دليل كفاءة، ولا سبب رسوب، ولا يستدعي مراجعة بشرية بذاته. **لا «كاشف ذكاء اصطناعي»**: لا استنتاج لمصدر الكود من الأسلوب أو التنسيق أو أنماط الرموز أو الاحتمالات.

| | |
|---|---|
| **`Disclosure Questionnaire`** | محكوم بنموذج التفعيل (Phase 4): مفتاح · إصدار · أسئلة كبيانات (صياغة · ترتيب · نوع الإجابة `yes_no/single_choice/multi_choice/free_text/text_list` · خيارات · مطلوب/اختياري · شرط ظهور · ربط اختياري بحقول الإفصاح القديمة). `ai_usage@1` **أساس توافق** = الحقلان قبل المرحلة؛ `ai_usage@2` **مسودة** بأسئلة المالكة السبعة (مفعَّلة للتطوير فقط في seed الديمو). الأسئلة **مجمَّدة** بعد أول تفعيل. |
| **`AI Disclosure`** (موسَّع) | كل إفصاح يسجّل **إصدار الاستبيان** الذي أُجيب به و`capture_mode` (`questionnaire` · `legacy_fields`)؛ الإجابات في `ai_disclosure_answer` **مع لقطة السؤال كما رآه المستخدم**. الشكل القديم للـAPI مقبول ويُسجَّل على `ai_usage@1`. الحقول القديمة (`declared_use` · `explanation`) تُشتق من الإجابات فيبقى كل قارئ قائم كما هو (`assertModeRespected` · سياق التقييم · المراجع). **ثابت** بعد التسجيل؛ التاريخ قبل 0016 `null` كما هو. |
| **`Integrity Signal`** | **واقعة مُهيكلة لا استنتاج**: النوع (سجل بيانات) · المصدر (**قائمة مغلقة من المصادر المرئية**: الإفصاح · المادة · المراجعات/المحاولات · إجابات التحقق · الفحوص الحتمية · الشرح · مراجع مُسمّى) · الاتجاه (`neutral_context` / `consistent_with_understanding` / `inconsistent_with_understanding`) · الأدلة المرتبطة · الملاحظة · الثقة · من أنتجها وبأي إصدار/سياسة · الوقت. **`outcome_effect = 'none'` بقيد**؛ لا عمود `fraud` ولا «درجة غش» ولا احتمال توليد. المُنتِجون الآن: `disclosure_recorded` (محايد؛ الإفصاح بنعم ليس سلبيًا) · `resubmission_recorded` · `deterministic_check_unmet` (الرؤية تتبع تصنيف الفحص) · نتائج التحقق. |
| **`Challenge`** | سجل الأنواع (Phase 4 موسَّع إلى ٩: شرح قرار · تعديل جزء · إصلاح خطأ جديد · قراءة كود · تنفيذ بديل · توقّع الناتج · تحديد خطأ · …) **كلها معطَّلة مسودة؛ لا يُفعَّل نوع بلا مصادقة (قيد)**. السياسة (`timing` · `skill_ids` · `difficulty` · `trigger_rule` · `max_challenges`) **غير مفعَّلة**. السجلات: `challenge_instance` (يُرفض إصداره في القاعدة والنطاق ما لم يكن النوع مُصادَقًا مفعَّلًا والسياسة فعّالة) → `challenge_response` → `challenge_result` (مراجع مُسمّى، **أعمى**، لا يحكم على عمله؛ النتيجة `understanding_shown/not_shown/inconclusive` **ملاحظة عن الفهم لا حكم على الأمانة**) → إشارة. |
| **الفصل** | الإشارة ≠ التقييم ≠ قرار التحقق. الإشارات **تُعرض** على سياق التقييم كنوع مدخل `integrity_signals`، و**أساس التوافق يستبعدها**؛ سياسة سياق مستقبلية مُصادَقة يمكن أن تضمّها. **لا شيء في الطبقة يمنح مستوى أو يزيله أو يخفضه**؛ السلّم أمامي كما هو. |
| **الخصوصية** | لا هوية ولا ملف شخصي في سياق التحدي أو إشاراته (`assertBlindPayload`)؛ المستخدم يرى إشاراته `user_facing` فقط (RLS)؛ الفحوص الداخلية تبقى مع التقييم. |
| **سلّم N0–N4** (`assessDisclosure`) | قائم في النطاق ومُختبَر، **غير موصول** بأي مسار؛ لم يُغيَّر. أي ربط مستقبلي بين الإشارات ونتيجة يمرّ بسياسة مُصادَق عليها. |

| الحقل | لماذا |
|---|---|
| `reason` **غير فارغ إلزاميًا** | «لا انتقال صامت، ولا انتقال بلا سبب مُسجَّل» |
| `actor_kind` + `role_performed` | قيد يرفض مراجعًا بشريًا بلا صفة مُسجَّلة |
| `payload` (`jsonb`) | **بتبرير**: أشكال الأحداث تختلف، والحقول القابلة للاستعلام **رُقِّيت أعمدة** |

## كيانات إضافية لزمت ولم تُطلب

| الكيان | لماذا كان لا بد منه |
|---|---|
| `Submission` · `SubmissionFile` | التسليم **يُقفل** ثم لا يُعدَّل؛ التصحيح تسليم جديد مرتبط. بلا هذا الكيان يصير «الدليل» بلا مادة |
| `HumanReview` | `FR-P-037`: مراجعة **عمياء** وسجل قرار غير قابل للتعديل |
| `SkillClaim` | «الحالة الحالية لمهارة» ≠ «الدليل». الدليل واقعة، والادعاء خلاصة الوقائع |
| `EvidenceTransition` | سجل السلّم. بلا سجل إضافة-فقط، الانتقال يصير تعديل عمود بلا تاريخ |
| `ActivitySpec` · `RubricVersion` | INV-2 · INV-7 يحتاجان نسخة منشورة **مجمّدة** يُشار إليها |
| `ModelCall` | INV-6: **استدعاء بلا صف هنا لم يحدث** |
| `MarketFact` | INV-4 في مكان واحد بدل تكراره في كل جدول يحمل رقمًا سوقيًا |
| `Consent` · `ReadinessScore` · `ScoreComponent` · `Job` | الموافقة إضافة-فقط · الدرجة بمكوّناتها ومحرّكها · الطابور المعاملاتي |

## ما لم يُنمذَج عمدًا

| البند | لماذا |
|---|---|
| **التراجع في السلّم** (`downgrade` · `revoke`) | ليس في v1.0. وقيد `transition_is_forward` يرفضه. إضافته لاحقًا **حالة مراجعة صريحة موسومة**، لا أثر جانبي لنشاط |
| **أوزان الدرجات** | `loadWeights()` **يفشل بصوت مسموع** حتى تُعتمد. رقم معقول المظهر يجعل نموذجًا غير مُعاير يبدو محسومًا |
| **جلسات الرفيق المهني** | لا استدعاءات نماذج في Phase 0، و`OPEN-023` مفتوح |
| **الملف العام كمحتوى** | `OPEN-016` مفتوح؛ بُني الهيكل والباب مغلق |
| **لوحة المؤسسات** | D-032: `org_id` محفوظ، ولا ميزة مؤسسية الآن |
