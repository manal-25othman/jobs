# R2: تصميم مشغّل اختبارات معزول لأعمال الخرّيجين (للعرض قبل أي تنفيذ)

> **الحالة (2026-11-26):** نُفّذ **مشغّل التطوير** على كود اصطناعي فقط، بموافقة المالكة في الجولة 2 (القرار 2).
> - **لم يُشغَّل أي كود لخرّيج حقيقي.** الرفض مفروض في الدومين (`assertRunnableOrigin`) وفي قاعدة البيانات (`test_run.origin = 'synthetic'`).
> - **الإنتاج يحتاج:** واجهة تشغيل بنواة معزولة (§2)، ومراجعة أمنية مستقلة، وموافقتك. نتائج المراجعة الداخلية في §9.
>
> الحالة السابقة: تصميم فقط، بموافقة مالكة المنتج على **التصميم** لا التنفيذ (القرار 3).
> - **لا يُنفَّذ أي كود للخرّيج حتى تعتمدي هذا التصميم.** اعتماده يعدّل قرار المالكة 5 («لا يُنفَّذ أي كود من مستودع الخرّيج»)، وهو CR-18.5 في CHG-018.
> - المصادر: دراسة Claude Ship (`CLAUDE-SHIP-FEASIBILITY.md`)، والوثيقة المرجعية FR-P-020 وFR-P-021 (فحوص حتمية قبل أي نموذج)، وFR-A-003 وFR-A-004.

## 1. الهدف والحدود

| ما يفعله | ما لا يفعله |
|---|---|
| يشغّل **اختبارات يكتبها فريق نَقْلة** لكل نشاط، على ملفات تسليم الخرّيج كما سُلّمت | لا يشغّل أوامر يقررها نموذج أو الخرّيج |
| يُخرج نتيجة منظّمة: لكل اختبار مرّ أو فشل، مع سبب مختصر مُنقّى | لا يقرر مستوى ولا جاهزية ولا اعتمادًا مهنيًا |
| تصبح النتيجة **فحصًا آليًا** في التقييم (FR-P-021)، يقرؤه المراجِع والنموذج لاحقًا | لا يصلح كود الخرّيج ولا يقترح كودًا |

## 2. متطلبات العزل (من قرار المالكة 3)

| المتطلب | التصميم |
|---|---|
| **لا شبكة** | حاوية بلا واجهة شبكة (`network: none`)؛ لا DNS؛ الحزم مثبَّتة مسبقًا في صورة ثابتة |
| **لا أسرار** | لا متغيرات بيئة من المنصة؛ لا ملفات اعتماد؛ لا مفاتيح سحابة؛ الحاوية لا ترى خزنة الأسرار ولا بيانات الخادم |
| **لا قواعد بيانات ولا بيانات مستخدمين** | المدخلات **فقط**: نسخة من ملفات التسليم، ومجلد الاختبارات للقراءة. لا اتصال بـPostgres ولا بالتخزين |
| **حدود الموارد** | معالج واحد؛ 512 MiB ذاكرة؛ قرص مؤقت 256 MiB؛ 64 عملية كحد أقصى (يمنع قنبلة العمليات)؛ **90 ثانية** لكل تشغيل؛ 10 ثوانٍ لكل اختبار. القيم مقترحة للتجربة وتُضبط بالقياس |
| **عزل كل محاولة** | حاوية جديدة لكل محاولة من صورة ثابتة، تُحذف بعد الانتهاء؛ لا مشاركة ملفات بين محاولتين أو خرّيجين |
| **أقل صلاحية** | مستخدم غير جذري؛ نظام ملفات للقراءة فقط عدا مجلد مؤقت؛ إسقاط كل صلاحيات النواة؛ seccomp افتراضي؛ بلا privileged |
| **عزل النواة** | تشغيل داخل sandbox بنواة معزولة (gVisor أو آلات افتراضية صغيرة على نمط Firecracker)، لا حاوية عادية فقط. التقنية تُختار مع الاستضافة (G1) |

## 3. البنية (إعادة استخدام ما هو موجود)

```
التسليم (submission + uploads، موجود) ─▶ مهمة تقييم (evaluation queued، موجود)
     ─▶ عامل R2 (خدمة صغيرة جديدة، بلا وصول للقاعدة): يستلم حزمة الملفات + معرّف حزمة الاختبارات + صورة ثابتة
     ─▶ sandbox: تشغيل الأوامر الثابتة ─▶ JSON نتيجة منقّاة
     ─▶ الخادم يسجّل النتيجة فحصًا آليًا (integrity/automated check، موجود) ─▶ محرّك التقييم الحتمي (موجود)
     ─▶ المراجِع البشري / اقتراح A13 لاحقًا (يقرأ النتيجة، لا يشغّل شيئًا)
```

- **المكوّن الوحيد الجديد:** عامل التشغيل. لا يتصل بقاعدة البيانات. يتسلّم المدخلات من الخادم، ويعيد النتيجة.
- **حزمة الاختبارات:** من مواد المراجِع (الجدول `activity_material`، audience = reviewer)، **ولا تُعرض للخرّيج**.
- **أسماء الاختبارات في النتيجة:** محايدة ومرتبطة بالبنود (مثل «سلوك القائمة الفارغة»)، فلا تكشف العيوب المزروعة.
- **التقنية:** صورة Node.js مثبّتة الإصدار، مع jsdom أو متصفح بلا واجهة لاختبارات الواجهات، مبنية مسبقًا بلا شبكة وقت التشغيل.

## 4. نموذج التهديد

| التهديد | التخفيف |
|---|---|
| كود يحاول الوصول للشبكة أو سرقة بيانات | لا شبكة؛ لا بيانات داخل الحاوية سوى ملفات الخرّيج نفسه |
| حلقة لا تنتهي أو استهلاك الموارد | حدود الوقت والذاكرة والعمليات؛ إنهاء قسري؛ تُسجَّل «تجاوز الوقت» نتيجةً |
| الهروب من الحاوية | نواة معزولة، ومستخدم غير جذري، وإسقاط الصلاحيات، وصورة دنيا، وتحديثات أمنية للمضيف |
| حقن تعليمات لنموذج لاحق عبر مخرجات الاختبار | المخرجات منظّمة ومقطوعة الطول ومنقّاة. النموذج **يشرح** ولا يقرر. حارس البوابة قائم |
| التلاعب بالاختبارات (كتابة كود يكتشف بيئة الاختبار) | اختبارات سلوكية متعددة، ومراجعة بشرية للحالات المشبوهة، وفحوص النزاهة القائمة |
| تسريب الاختبارات المخفية | لا تُعاد أكواد الاختبارات ولا أسماؤها الداخلية للخرّيج |
| تعطّل العامل | التقييم يتحول إلى «مراجعة بشرية» (FR-A-004)، ولا نتيجة تخمينية |

## 5. الخيارات المقارنة

| الخيار | المزايا | العيوب | التوصية |
|---|---|---|---|
| **أ. عامل معزول تملكه نَقْلة** في منطقة الاستضافة المعتمدة | حتمية كاملة؛ بلا مشاركة بيانات مع طرف ثالث؛ يحترم موطن البيانات | يحتاج تشغيلًا وصيانة | **موصى به** |
| ب. بيئات Managed Agents (Anthropic) | حاويات جاهزة بشبكة محدودة | بيانات الخرّيج تخرج إلى مزوّد (`OPEN-023`)؛ مصمَّمة لتشغيل وكلاء، لا لأوامر حتمية | لا، لهذا الغرض |
| ج. أداة تنفيذ الكود في Claude API | معزولة، وبلا إنترنت | النموذج يقرر ما يُشغَّل؛ وجود Node.js غير موثَّق | لا |

## 6. التكلفة
- **حوسبة:** نحو 10 / 100 / 1,000 ساعة معالج شهريًا لكل 100 / 1,000 / 10,000 خرّيج (3 تسليمات، ودقيقتان للتشغيل).
- **السعر:** يُتحقق منه عند اختيار الاستضافة (G1). لم يُذكر سعر غير متحقَّق منه.
- **التطوير:** العامل، والصورة، واختبارات الأنشطة الثلاثة، واختبارات الأمان (§7)، وربطه بالتقييم.

## 7. التحقق قبل التشغيل الأول
1. **اختبارات هجومية:** كود يحاول الاتصال بالشبكة، وقراءة متغيرات البيئة، وتجاوز الذاكرة، وقنبلة عمليات، والكتابة خارج المجلد. كلها يجب أن تفشل بأمان.
2. **الحتمية:** التسليم نفسه يعطي النتيجة نفسها في كل تشغيل.
3. **مراجعة أمنية مستقلة** للصورة وإعدادات العزل.
4. **وضع الظل:** تُحسب النتائج ولا تدخل التقييم، حتى تُقارن بحكم المراجِعين.

## 8. ما يتطلب قرارك
1. اعتماد تعديل القرار 5 (CR-18.5) والخيار (أ).
2. حدود الموارد المقترحة.
3. من يكتب اختبارات الأنشطة ويراجعها (محتوى تقييمي يحتاج خبيرًا).

## 9. المراجعة الأمنية الداخلية والتنفيذ التجريبي (2026-11-26)

**ما نُفّذ** (`apps/runner`):
- **واجهة تشغيل للتطوير `namespace-dev`:**
  - نطاقات Linux منفصلة: شبكة، وعمليات، وIPC، وUTS، وتركيب الملفات.
  - مجموعات تحكّم (cgroups) لكل محاولة: الذاكرة، وعدد المهام، وحصة المعالج.
  - المستخدم nobody، مع `no_new_privs` وإسقاط كل الصلاحيات، وبيئة فارغة.
  - جذر للقراءة فقط، وإخفاء `/home` و`/root` و`/var` و`/run` و`/opt`، مع إعادة ربط المتصفح وحده للقراءة.
  - مجلد مؤقت محدود الحجم، وتنظيف كامل بعد كل محاولة، وكنس للمحاولات اليتيمة.
- **مرفوضة في الإنتاج:** هذه الواجهة ليست حدًّا أمنيًا كافيًا لكود غير موثوق، لأن Docker أو النطاقات وحدها لا تكفي (قرار المالكة 2).
- **المتصفح داخل الصندوق والتحقق خارجه:**
  - يُشغَّل Chromium بصندوقه الخاص داخل الصندوق المعزول، والصفحة تُخدَم من الذاكرة، وكل طلب آخر يُحظر ويُعدّ.
  - **المقارنات والقيم المتوقعة تبقى في المشغّل الموثوق خارج الصندوق،** والاستعلامات عبر محرك المتصفح (CDP) أو عالم معزول.
  - النتيجة: كود الخرّيج لا يقرأ الاختبارات المخفية، ولا يزوّر النتيجة بتعديل دوال الصفحة.
- **الحدود قابلة للمعايرة** ضمن حدود صلبة (`R2_LIMIT_BOUNDS`).
  - `maxProcesses` يعدّ العمليات **والخيوط** معًا؛ المتصفح يحتاج بضع مئات، فالافتراضي 512.
- **كل نتيجة مربوطة** برمز الإيداع وبتجزئة اللقطة، ولا تحمل إلا تسميات محايدة؛ `assertTestRunResult` يرفض ما يكشف داخل الاختبار.

**اختبارات الهجوم (كلها ناجحة، على كود اصطناعي):**

| الهجوم | النتيجة |
|---|---|
| الاتصال بقاعدة بيانات المنصة وخدمات المضيف والإنترنت، واستعلام DNS | محجوب: لا شبكة |
| قراءة متغيرات البيئة، والمستودع، و`.env`، ومجلد root، ومحاولة أخرى، و`/proc` للمضيف | فارغة أو غير موجودة |
| الكتابة في `/etc` و`/usr` وملفات التسليم | نظام ملفات للقراءة فقط |
| قنبلة العمليات | محدودة بسقف المهام |
| استنزاف الذاكرة | أوقفته مجموعة الذاكرة، لا الوقت |
| ملء القرص | يتوقف عند حجم المجلد المؤقت (ENOSPC) |
| حلقة لا تنتهي، وعملية في الخلفية | تُقتل من الخارج؛ لا يبقى مجلد ولا مجموعة تحكّم |
| صفحة تعدّل دوال DOM والتخطيط لتزوير النجاح | تُقاس الحقيقة؛ وتُرفع إشارة خداع |
| صفحة ترسل إلى المنصة، أو localhost، أو عنوان بيانات السحابة 169.254.169.254 | تُحظر وتُعدّ |
| صفحة معلّقة، وصفحة تستنزف الذاكرة | مهلة لكل اختبار؛ المحاولة تنتهي بنتيجة محدودة |
| كود من أصل «graduate» | مرفوض قبل التشغيل |

**مخاطر متبقية** تمنع التشغيل على كود حقيقي حتى تُعالج:
1. **النواة مشتركة مع المضيف.** النطاقات لا تعزل ثغرات النواة، فيلزم gVisor أو آلة افتراضية صغيرة.
2. **لا seccomp مخصَّص** في واجهة التطوير. المتصفح يستخدم صندوقه الخاص، لكن عملية الغلاف لا.
3. **يحتاج صلاحية root على المضيف** لإنشاء النطاقات والمجموعات. في الإنتاج يجب أن يعمل العامل على مضيف مخصَّص بلا أي بيانات للمنصة.
4. **الخداع الذي يمر بالاختبارات** (مثل تعديل خدمة البيانات الوهمية) يُكتشف بإشارات نصية فقط، لذلك تبقى المراجعة البشرية للحالات المشبوهة.
5. **مراجعة أمنية مستقلة** لم تتم بعد.
