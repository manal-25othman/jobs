# نَقْلة / NAQLA — AI Boundary
**الإصدار:** 0.1.0 · **التاريخ:** 2026-09-26 · **الحالة:** معماري — **لا استدعاءات نماذج في Phase 0**

> **الخط الفاصل في جملة واحدة:**
> **الذكاء الاصطناعي يشرح ويقترح ويصوغ. والقواعد الحتمية وحدها تقرّر ما هو مُثبت.**

---

## ١. لماذا هذا الخط قبل الكود

نَقْلة تبيع شيئًا واحدًا: **أن ما يقوله ملف المستخدم صحيح**. ولو استطاع نموذج لغوي أن يرفع مهارة أو يكتب دليلًا، فالمنتج يصير مولّد سيَر بواجهة أجمل. ولأن هذا الخط لا يُستعاد بعد كسره، فُرض في البنية قبل أن يوجد استدعاء واحد.

**الحالة اليوم:** لا استدعاء نموذج في المستودع. لا مفتاح مزوّد في `ENV_SPEC`، **واختبار يفشل إن أُضيف** — لأن `OPEN-023` (شروط معالجة البيانات لدى المزوّد) ما زال حاجبًا.

---

## ٢. ما يجوز للنموذج

| المجال | ما يفعله | ما يبقى حتميًا |
|---|---|---|
| **الشرح** | يشرح لماذا مهارة عند `practiced` لا `demonstrated` | **الحالة نفسها** من `assertTransitionAllowed` |
| **الصياغة المقترحة** | يصوغ بند سيرة أو `Headline` من دليل قائم | **ماذا يجوز عرضه** من `cvEligibility` / `linkedInEligibility` |
| **إعادة صياغة السيرة ولينكدإن** | يقترح بديلًا لجملة ضعيفة | **الدرجة ومكوّناتها** من `computeReadiness` |
| **التلخيص** | يلخّص تقييمًا طويلًا | **الدرجات والمبررات** من `evaluation_criterion_score` |
| **التغذية الراجعة** | يشرح ملاحظة المُقيِّم بلغة أوضح | **النتيجة** من الرُبريك المنشور |
| **مسودة دراسة الحالة** | يكتب الأقسام الأربعة من تقييم | **الأرقام والمهارات** من `evaluation_result` |
| **توصيات التعلّم** | يرتّب مصادر مُتحقَّقة | **الفجوة نفسها** محسوبة من متطلبات الدور والادعاءات |

**الحد المشترك:** النموذج يتصرف في **العبارة**، لا في **الواقعة**.

## ٣. ما لا يجوز — وكيف يُمنع بنيويًا

| ممنوع | المنع ليس سياسة مكتوبة بل: |
|---|---|
| **اختلاق دليل** | `evidence.evaluation_result_id` مطلوب لقوة المنصة · **RLS لا تمنح أي عميل كتابة على `evidence`** |
| **ترقية مهارة غير مدعومة** | `assertTransitionAllowed` ترفض `actor: 'ai_agent'` بـ**INV-3** · وقيد `transition_actor_is_not_agent` في القاعدة |
| **وسم `Demonstrated` أو `Verified`** | كل صف في `TRANSITIONS` يحمل `aiMayExecute: false` **كنوع حرفي** لا متغيّر · و`verified` يلزمه `human_reviewer_id` |
| **تعديل تاريخ التقييم** | `UPDATE` و`DELETE` **مسحوبتان** من `evaluation_result` |
| **نشر ادعاء مهني** | `asset_published_needs_approval` يرفض النشر بلا `user_approved_at` |
| **تجاوز موافقة المستخدم** | زر «معاينة» ثم «اعتماد» — ولا زر «تطبيق» (§9) |

**ثلاث طبقات، كل منها كافية وحدها:** نوع في TypeScript · حارس في `packages/domain` · قيد في PostgreSQL. لأن الطبقة الواحدة تُنسى.

## ٤. تجريد المزوّد — بوابة واحدة

```
  وكيل / حالة استعمال
        │  يطلب قدرة، لا مزوّدًا
        ▼
  ┌──────────────────────────────┐
  │   AI Gateway  (LBD-06)       │
  │  · قياس كل استدعاء (INV-6)   │
  │  · سقف ميزانية وتدرّجها      │
  │  · تنفيذ منطقة البيانات      │
  │  · تسجيل الغرض والمخرَج      │
  └──────────────────────────────┘
        │  محوّل لكل مزوّد
        ▼
   مزوّد أ   ·   مزوّد ب   ·   منفّذ حتمي
```

**أربعة أسباب، لا سبب تجميلي واحد:**
1. **INV-6** يوجب قياس كل استدعاء. مع استدعاءات متناثرة يصير القياس غير قابل للتحقق.
2. **`OPEN-023`**: مناطق المزوّد قد لا تطابق منطقة التخزين. البوابة **المكان الوحيد** الذي يُفرض فيه ذلك.
3. **الرفيق المهني (A01)** يحتاج تدرّجًا ثلاثيًا: `كامل → منخفض التكلفة → حتمي`، **ولا يتوقف أبدًا**. مستحيل بلا بوابة.
4. **١٩ وكيلًا** لا تسعة عشر تكاملًا.

**والخطر الحقيقي في التجريد نفسه:** أن يُصمَّم على «القاسم المشترك الأدنى» فتُفقد مزايا المزوّد (مخرجات مهيكلة، تخزين سياق مؤقت). لذلك يُصمَّم حول **قدرات** (`structuredOutput` · `longContext` · `cheapDraft`) لا حول أبسط واجهة ممكنة.

### شكل الواجهة (عقد، لا تنفيذ)
```
requestCompletion({
  purpose,          // إلزامي — بلا غرض لا يُقبل الاستدعاء
  capability,       // قدرة مطلوبة لا اسم مزوّد
  budgetTier,       // full | low_cost | deterministic_only
  userId,           // للقياس والحدود
  input,
}) -> { output, gatewayCallId, provider, model, tokens, costUnits }
```
`gatewayCallId` **ليس اختياريًا في الإرجاع**: `assertMeteredModelCall` ترفض استدعاءً بلا قياس، فالاستدعاء غير المُسجَّل **لم يحدث**.

## ٥. الإفصاح — لا يخفض درجة أبدًا

الأوضاع الثلاثة على **مواصفة النشاط** لا على اختيار المستخدم: `ai_prohibited` · `ai_assisted` · `ai_expected`.

**القاعدة الحاكمة:** الإفصاح **لا يخفض الدرجة بذاته**. المهم: ماذا فعل المستخدم، وبماذا ساعده الذكاء الاصطناعي، **وهل يستطيع أن يشرح عمله ويدافع عنه**.

مفروضة ثلاث مرات:
- **لا عمود عقوبة في `ai_disclosure`** — حقل غير موجود لا يُساء استخدامه.
- `scorePenaltyApplied: false` **نوع حرفي** في `DisclosureAssessment`، فلا يمكن إرجاع `true`.
- `assertDisclosureDidNotLowerScore` ترمي إن نقصت الدرجة بعد الإفصاح.

**سلّم N0–N4 غير عقابي:** إشارة واحدة **ضجيج**؛ إشارتان فأكثر **تفتحان محادثة بشرية** لا حكمًا آليًا؛ ومن يشرح عمله ويدافع عنه يعود إلى `N1` مهما تعددت الإشارات.

## ٦. ما يراه النموذج وما لا يراه

| يراه | لا يراه |
|---|---|
| التسليم موضع التقييم | ملف المستخدم وأدلته السابقة — **منع انحياز** (doc 11 §5) |
| الرُبريك المنشور | تفاصيل فحوص `assessment_only` |
| مواصفة النشاط | هوية المستخدم في المراجعة العمياء |
| الدليل القائم عند اقتراح صياغة | محادثات الرفيق الخاصة بمستخدم آخر |

---

## ٧. عند العطل — الوضع الآمن

| العطل | السلوك |
|---|---|
| انقطاع نموذج النزاهة | النتيجة `undetermined` · **المستوى الأدنى** · مراجعة بشرية متاحة |
| فشل المُقيِّم | إعادة محاولة **واحدة** ثم طابور بشري. **ولا نتيجة تخمينية إطلاقًا** |
| تجاوز الميزانية | تدرّج الرفيق: كامل → منخفض التكلفة → حتمي. **لا يتوقف** |
| التباس | **الحالة الأكثر تحفظًا** |

**«لا دليل» نتيجة مشروعة وتُعرض بوضوح.** المنتج الذي لا يستطيع قول «لم تُثبت بعد» لا يستطيع قول «أُثبتت» بمصداقية.

## ٨. ما هو مُثبت الآن وما ينتظر

| البند | الحالة |
|---|---|
| لا استدعاء نموذج في المستودع | ✅ **مُثبت** — لا اعتمادية مزوّد في أي `package.json` |
| لا مفتاح مزوّد في الإعدادات | ✅ **مُثبت باختبار يفشل** إن أُضيف |
| الوكيل لا ينفّذ انتقالًا | ✅ **مُثبت** في TypeScript وفي القاعدة |
| الأصل لا يُنشر بلا اعتماد | ✅ **مُثبت** بقيد قاعدة |
| الإفصاح لا يخفض درجة | ✅ **مُثبت** بالنوع وبالاختبار |
| تنفيذ البوابة | ⛔ **لم يُبنَ** — عقد مكتوب فقط |
| اختيار المزوّد | ⛔ **حاجب**: `OPEN-023` قبل أي استدعاء |

## ٩. طبقة الوكلاء (الشريحة 02) — ما بُني وأين يقف الخط

```
  حدث (تقييم اكتمل · دليل Demonstrated · ادعاء غير مدعوم)
        │
        ▼
  المُنسّق الحتمي  ── قواعد R1–R5، لا نموذج ──▶  وكيل واحد (توظيف | تقني)
        │
        ▼
  AgentGateway: حجب السياق → ميزانية → مزوّد → مخطط → قواعد النطاق → مصدر
        │
        ▼
  agent_proposal (generated → validated → awaiting_user → approved | rejected | superseded)
        │
        ▼  فقط للصياغات، وفقط بيد المستخدم
  معاينة → تعديل اختياري → اعتماد صريح → أصل مهني فعّال  (نفس الجدول ونفس القيود)
```

**ما يستطيعه الوكيل:** يقترح `cv_bullet` · `technical_feedback` · `rubric_explanation` · `technical_next_action` … (١٧ نوعًا مغلقًا).
**ما لا يستطيعه بنيويًا:** لا مسار كتابة، لا مفتاح فعل في الحمولة، لا نوع اقتراح خارج تخصصه، لا `Verified` حتى توصيةً (D-059).
**المزوّد اليوم:** `local-test` — اختباري غير إنتاجي، يُرفض في الإنتاج. لا استدعاء لأي نموذج خارجي؛ `verify-boundaries` يرفض أي SDK.
