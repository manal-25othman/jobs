# صفحة طلبات الإجازة — مواد البداية

> محتوى تجريبي غير معتمد مهنيًا · للتجربة الداخلية في نَقْلة فقط · مشروع أصلي كُتب لهذا النشاط.
> **هذه المواد سرّية:** لا تنشريها ولا تدفعيها إلى مستودع عام. اقرئي قسم Git أدناه.

## سياق العمل

يريد فريق الموارد البشرية صفحة يرى فيها الموظف طلبات إجازته السابقة، تُجلب من خدمة داخلية. بدأ زميل العمل على الصفحة ثم انتقل إلى مهمة أخرى، وترك بلاغًا:

> «بعد فشل التحميل والضغط على إعادة المحاولة، تظهر الطلبات لكن مؤشر التحميل لا يختفي.»

الوصف الكامل ومعايير القبول في `BRIEF.md`.

## محتويات المجلد

| الملف | ما هو |
|---|---|
| `BRIEF.md` | وصف الصفحة ومعايير القبول |
| `index.html` | هيكل الصفحة الذي بدأه الزميل |
| `styles.css` | أنماط أولية |
| `app.js` | تحميل الطلبات وعرضها (كتبه الزميل، وفيه سبب البلاغ) |
| `mock-api.js` | خدمة وهمية تحاكي خدمة الموارد البشرية (لا تعدّليها) |
| `data/leave-requests.json` | البيانات التي تُرجعها الخدمة الوهمية |

## التشغيل

الصفحة تجلب البيانات بـ`fetch`، فشغّلي خادمًا محليًا من داخل المجلد:

```bash
npx serve .            # يتطلب Node.js
python3 -m http.server 8080
```

ثم افتحي العنوان الظاهر. لتجربة حالات الخدمة أضيفي `?scenario=` إلى العنوان:

| العنوان | ما تُرجعه الخدمة |
|---|---|
| `?scenario=ok` (الافتراضي) | قائمة الطلبات |
| `?scenario=empty` | قائمة خالية |
| `?scenario=error` | خطأ 500 دائمًا |
| `?scenario=slow` | القائمة بعد تأخير 3 ثوانٍ |
| `?scenario=flaky` | خطأ 500 في المحاولة الأولى، ثم القائمة (لإعادة إنتاج البلاغ) |

## المطلوب منك

1. ابني الصفحة ببنية دلالية، واجعليها مقروءة على الجوال والحاسوب **دون تمرير أفقي**.
2. اعرضي حالات البيانات كلها:
   - جارٍ التحميل؛
   - خطأ مع إمكانية إعادة المحاولة؛
   - لا طلبات؛
   - الطلبات.
3. حدّدي أين سبب البلاغ في الكود المقدَّم ولماذا أنتج هذا العَرَض، ثم أصلحيه **من سببه**.
4. اشرحي في ملاحظة قصيرة، بالإشارة إلى كودك، أين تُحفظ الحالة وكيف تصل البيانات إلى الشاشة.
5. اذكري قرارين اتخذتِهما ولماذا. إن وجدتِ تعارضًا بين الوصف والبيانات فاذكريه وما قرّرتِه.
6. اعملي على فرع بإيداعات صغيرة موصوفة، وقدّمي Pull Request يشرح ما تغيّر ولماذا.

## Git: مستودع **خاص** دائمًا

هذه المواد سرّية، فلا تستخدمي مستودعًا عامًا أبدًا.

1. أنشئي على GitHub مستودعًا **خاصًا (Private)** باسم من اختيارك.
2. ارفعي ملفات البداية كما هي في إيداع أول على `main`، مثل `chore: starter files`.
3. أنشئي فرعًا للعمل، مثل `feature/leave-requests`، واعملي عليه بإيداعات صغيرة توضّح رسالةُ كلٍّ منها ما تغيّر.
4. افتحي Pull Request من فرعك إلى `main` **داخل المستودع الخاص نفسه**. اكتبي في وصفه ما تغيّر ولماذا.
5. امنحي المراجِع صلاحية **قراءة** مؤقتة: Settings ← Collaborators ← Add people، ثم أضيفي حساب المراجِع الذي يزوّدك به فريق نَقْلة.
6. بعد انتهاء المراجعة يمكنك إزالة صلاحيته.

لا تتصل نَقْلة بحسابك على GitHub، ولا تقرأ مستودعك، ولا تشغّل الكود. المراجِع البشري وحده يفتح الرابط بالصلاحية التي منحتِها.
